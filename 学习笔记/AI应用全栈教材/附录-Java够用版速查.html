附录　Java 够用版速查
28 小时，从「看不懂」到「能改、能接」

这份附录解决一个很具体的问题：你的目标岗位 JD 里写着「Java Spring Boot 或 Python」，而你不想花四个月学 Java。这里给的是「够用版」——能读懂公司那套系统、能改、能对接，明确不学 JVM 调优、不学 Spring Cloud 全家桶。

这份附录怎么用
先看　下面那个「三个能」的验收标准，判断自己是否已经够了
照做　十四天路线，每天 2 小时，其中第 5–7 天最关键
备查　注解表、调用链、事务三坑——面试前看一遍
别做　最后那节「明确不用学的」，省下来的时间投到评估和工具调用上

一、用三个「能」定义程度

「学到什么程度」很难自我判断，但下面三件事可以诚实检验。三件都能做到，就够了。

能力具体表现检验方式
能读懂给你一个现成模块，能说清一次请求经过了哪些类、查了哪些表、鉴权在哪一步随便挑一个你熟的接口，从前端调用一路画到 SQL
能对接给一份接口代码，知道怎么调、参数是什么、错误码什么意思、写回时要注意什么用 Python 或 curl 调通它，并处理三种错误
能改能加一个接口、加一个查询条件、加一个字段，不把系统改坏提一个真实的改动 PR，让别人 review

做不到第一条，学再多语法也没用——因为你的工作场景不是「写新系统」，是「在已有系统上接东西」。

二、十四天路线（每天 2 小时，共 28 小时）

天做什么产出 / 验收
D1–2语法速通。对比 TypeScript 学：类型声明、泛型、异常（checked vs unchecked）、值传递、String 不可变、集合（List / Map）让 AI 生成 TS/Java 对照代码，能读懂同一逻辑的两种写法
D3–4Spring Initializr 生成项目，写一个 GET + 一个 POST，连 H2 内存库能 curl 通，能看到 SQL 日志
D5–7读公司现有代码（最重要）。挑一个你熟的业务，从前端调的那个接口一路读到 SQL，画出调用链画出一张图：Filter → Interceptor → Controller → Service → Mapper → DB，标出鉴权点、事务边界、异常处理
D8–10改一个真实需求：加个字段、加个查询条件。遇到报错就查一个真实的小 PR
D11–12补事务与权限：@Transactional 加在哪一层、三个失效场景、token 在哪校验能说清「为什么这个事务没回滚」
D13–14写一个 Java 侧的「调用 AI 服务」客户端（对，反向对接）能调通你自己写的 FastAPI 服务，处理超时与重试

D5–7 是整段的核心。很多人学 Java 的方式是买一本《Java 核心技术》从头读到尾，四个月起步，读完还是不会读公司代码——因为书教的是语言，你要的是框架加业务。公司代码就是最好的教材，而且读完立刻能用。

D13–14 这一条是有意加的。它的价值在于：你会从「Java 侧」看待你的 Python 服务，包括它怎么被调用、超时怎么设、错误怎么传。这个视角在面试里很好用，因为它证明你不是只会写一端的人。

三、必会注解（12 个，够用）

注解作用常见坑
@RestController标记控制器，返回 JSON和 @Controller 的区别是后者返回视图名
@RequestMapping路由前缀写在类上做前缀，方法上写具体路径
@GetMapping / @PostMapping具体路由GET 参数用 @RequestParam，POST body 用 @RequestBody
@RequestBodyJSON 反序列化成对象缺它会得到全 null 的对象，不报错——最阴的一个坑
@RequestParam取 query 参数名字不一致时要用 @RequestParam("x")
@PathVariable取路径变量/order/{id} 对应 @PathVariable Long id
@Service标记业务层 Bean不加就没有 Bean，注入时为 null
@Autowired依赖注入类不是 new 出来的，是容器给你的——前端出身最大的思维转换
@Configuration + @Bean手写 Bean 定义第三方库的对象通常这样注册
@Transactional事务加在 Service 层；三个失效场景见下节
@Mapper / @MapperScanMyBatis 接口扫描忘了扫就报「找不到 Mapper」
@Valid / @NotNull参数校验不加 @Valid 校验注解不生效

四、请求的完整流转（最值钱的一张图）

图 A-1　请求流转：这张图要能默画

这张图之所以重要，是因为它同时回答三个问题：要加东西加在哪、鉴权在哪、事务在哪。面试里问「你们系统的鉴权怎么做的」「事务加在哪一层」，答得出这张图的人有明显优势。

五、事务的三个失效场景（面试标准题）

@Transactional 失效有三个经典原因，答不上来说明只是看过文档。

场景为什么失效正确做法
同类内部调用Spring 事务基于代理。同类方法内部调用不走代理，注解不生效拆到另一个 Bean；或注入自身代理；或改用编程式事务
异常被 catch 吞掉默认只对 RuntimeException 回滚。catch 后不抛出，容器认为成功重新抛出，或 @Transactional(rollbackFor = Exception.class)
方法非 public代理无法拦截 private / protected 方法改成 public，或把事务边界上移到 public 方法

还有一个常被提到的：事务里做远程调用。这会长时间占用数据库连接，在高并发下直接耗尽连接池。规则是：事务里只做数据库操作，调用外部服务（包括你的 AI 服务）放到事务外。

这一条和你的项目直接相关：如果 Java 主系统要在事务里调用你的 Python AI 服务，那个事务会持有连接 9 秒以上。正确的做法是事务提交后再异步调用，或者干脆由前端直接调 AI 服务（第 5 章的侧车架构）。

六、面试话术：怎么划边界

AI 全栈岗问 Java，不会问 JVM 调优和微服务治理——那是 Java 后端岗的问题。他们真正想确认的是：「你能不能跟我们的后端系统接上？」

一段可以直接用的回答
「我的 Java 是应用层视角：能读懂现有系统、能改、能对接。
具体说，我能从前端调的一个接口一路读到 SQL，知道鉴权和事务在哪一层，
能加接口、加字段、加查询条件；也能从 Java 侧调外部服务，处理超时和重试。

我不做 Java 架构设计——那不是我的定位。我的强项是在已有系统旁边
把 AI 能力接进去：独立的 Python 服务、检索链路、评估体系，
以及前端那套交互。这三块加起来，正好是一个 AI 应用全栈要交付的范围。」
这段话的作用不是「谦虚」，是重新定义评价标准：
把它从「你 Java 有多深」转向「你能不能交付一个完整系统」。
而后者恰好是你有证据、他没有理由质疑的地方。

如果对方追问「那你为什么不深入学 Java」，可以答：

「我评估过投入产出。我的目标是 AI 应用全栈，JD 里后端写的是『Java 或 Python』，而 AI 生态的 SDK、评估工具、编排库都以 Python 为一等公民。Java 对我最大的价值是理解企业系统的边界和约束，让我能把 AI 接进去——这个层面 L2 就够。省下的四个月我投在了评估体系和工具调用上，那两块的稀缺性更高。」

这个回答的结构是：承认取舍 + 给出依据 + 说明投入去了哪。它把一个「短板」变成了「有判断力的选择」。

七、明确不用学的

内容为什么不用学
JVM 调优、GC 参数那是 Java 后端/架构师的活。你不需要为 JVM 性能负责
Spring Cloud 全家桶（Nacos / Sentinel / Gateway / Feign）微服务治理属于平台团队。你只需要知道「服务之间怎么调」这个概念
Java 侧的 AI 框架（LangChain4j 等）生态不成熟，且你的 AI 逻辑本来就该用 Python 写。学了也无法复用
手写 JDBC / Servlet / 原生 MyBatis 原理知道有这层就行。面试问了能说一句「底层是 JDBC」即可
Java 并发编程（AQS / 线程池源码）除非你去面 Java 后端岗，否则用不上

最后一项值得多说一句：不要因为「怕被问倒」而去学这些。被问倒一次的成本，远小于花三个月学一个用不上的东西。而且面试官问深了，你答「这块我不深入，我的重点是系统集成」，比硬撑要好——硬撑被识破，比承认边界损失大得多。

四个学习方式上的建议
  1. 不要看课，直接读公司代码。四个月的课不如三天的源码阅读。语言是工具，你要的是这套系统的形状。
  2. 对比 TypeScript 学语法。让 AI 生成同一逻辑的两种写法，比看教程快十倍。
  3. 用 AI 写代码学得快，但会产生「我会了」的错觉。检验方式只有一个：断网，从空白文件开始，能不能写出骨架。
  4. 侧车 AI 服务一定用 Python。Java 的用途是「读和接」，不是「写 AI 逻辑」。这条边界一旦模糊，你会多花三个月且没有收益。
附录小结
  • 三个「能」定义程度：能读懂、能对接、能改。做到就够了。
  • 十四天 28 小时，其中 D5–7 读公司代码最关键，D13–14 反向对接自己的服务最加分。
  • 12 个注解够用；最阴的坑是漏 @RequestBody（得到全 null，不报错）。
  • 请求流转那张图要能默画，它同时回答「加在哪、鉴权在哪、事务在哪」。
  • 事务三失效：同类内部调用、异常被吞、方法非 public。另外事务里不要做远程调用。
  • 话术的核心是重新定义评价标准：从「Java 有多深」转向「能不能交付完整系统」。
  • 明确不学：JVM 调优、Spring Cloud、Java 侧 AI 框架、并发源码。
