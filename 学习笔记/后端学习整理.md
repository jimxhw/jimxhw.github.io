# JavaSE 核心知识点总结

## 一、JavaSE 概述

### 1.1 Java 语言特点

* 跨平台性：依托JVM（Java虚拟机），一次编译（生成.class字节码文件），多处运行
* 面向对象：封装、继承、多态三大核心特征，符合现实世界建模逻辑
* 安全性：提供字节码校验、安全管理器等机制，避免恶意代码执行
* 健壮性：自动垃圾回收（GC）避免内存泄漏，强类型检查减少类型错误
* 分布式：支持HTTP、TCP/IP等协议，便于开发分布式应用

### 1.2 JDK、JRE、JVM 关系

JDK（Java Development Kit）：Java开发工具包，包含JRE、编译器（javac）、调试器等开发工具，是开发Java程序的基础。

JRE（Java Runtime Environment）：Java运行环境，包含JVM和Java核心类库，是运行Java程序的必要环境。

JVM（Java Virtual Machine）：Java虚拟机，负责将字节码文件解释为对应操作系统的机器指令，是跨平台特性的核心。

关系：JDK ⊇ JRE ⊇ JVM

## 二、核心基础

### 2.1 环境搭建与第一个程序

#### 2.1.1 环境变量配置

* JAVA_HOME：指定JDK安装路径，便于后续工具（如Maven）定位JDK
* Path：添加JDK的bin目录（javac、java等命令），使系统能在任意目录执行Java命令
* 验证：cmd中输入 `javac -version` 和 `java -version`，显示版本信息则配置成功

#### 2.1.2 第一个Java程序

```java
// HelloWorld.java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, JavaSE!");
    }
}
```

执行步骤：

1. 编译：`javac HelloWorld.java`，生成 HelloWorld.class 字节码文件
2. 运行：`java HelloWorld`，JVM加载并执行字节码，输出结果

注意：类名必须与文件名一致（public修饰的类），main方法是程序入口（固定格式）。

### 2.2 基本语法

#### 2.2.1 标识符与关键字

标识符：用于命名类、方法、变量等的名称，规则：由字母、数字、_、$组成，不能以数字开头，区分大小写，不能使用关键字。

关键字：Java预留的特殊单词（如public、class、static、void、if、for等），具有特定语义，不能作为标识符。

#### 2.2.2 注释

* 单行注释：// 注释内容（仅当前行有效）
* 多行注释：/* 注释内容 */（可跨多行，不嵌套）
* 文档注释：/** 注释内容 */（用于生成API文档，可包含参数、返回值等说明，配合javadoc命令使用）

#### 2.2.3 变量与常量

变量：存储可变数据的容器，声明格式：`数据类型 变量名 = 初始化值;`（如 int age = 20;）

常量：存储不可变数据，用final修饰，声明格式：`final 数据类型 常量名 = 值;`（如 final double PI = 3.14159;，常量名通常全大写）

#### 2.2.4 数据类型

Java是强类型语言，数据类型分为两大类：

1. 基本数据类型（8种）：

   1. 整数型：byte（1字节）、short（2字节）、int（4字节，默认）、long（8字节，声明时需加L后缀）
   2. 浮点型：float（4字节，声明时需加F后缀）、double（8字节，默认）
   3. 字符型：char（2字节，存储Unicode字符，用单引号包裹，如 'A'、'中'）
   4. 布尔型：boolean（1字节，值为true或false，不能用0/1代替）
2. 引用数据类型：类（class）、接口（interface）、数组、枚举（enum）等，存储对象的引用（内存地址），默认值为null。

#### 2.2.5 类型转换

* 自动类型转换（隐式）：小范围类型 → 大范围类型（如 byte → short → int → long → float → double，char → int），无需手动处理。
* 强制类型转换（显式）：大范围类型 → 小范围类型，需用括号指定目标类型，可能丢失精度或溢出，格式：`(目标类型) 变量名`（如 double d = 3.14; int i = (int)d; // i=3）

#### 2.2.6 运算符

* 算术运算符：+、-、*、/（整数除法取商）、%（取余）、++（自增）、--（自减）
* 赋值运算符：=、+=、-=、*=、/=、%=
* 比较运算符：==（判断相等）、!=（不等）、>、<、>=、<=，结果为boolean类型
* 逻辑运算符：&&（短路与）、||（短路或）、!（非），操作数为boolean类型，结果为boolean
* 位运算符：&（按位与）、|（按位或）、^（按位异或）、~（按位取反）、<<（左移）、>>（右移）、>>>（无符号右移），操作数为整数型
* 三元运算符：`条件表达式 ? 表达式1 : 表达式2`，条件为true时执行表达式1，否则执行表达式2

#### 2.2.7 流程控制

1. 顺序结构：代码从上到下依次执行，默认流程
2. 分支结构：

   1. if-else：`if(条件){...} else if(条件){...} else{...}`
   2. switch-case：用于多值匹配，支持byte、short、int、char、枚举、String（JDK7+），格式：
      `switch(变量) { ``    case 值1: 代码块1; break; // break防止穿透 ``    case 值2: 代码块2; break; ``    default: 默认代码块; ``}`
3. 循环结构：

   1. for循环：`for(初始化; 条件; 迭代){...}`，适合已知循环次数
   2. while循环：`while(条件){...}`，适合未知循环次数，先判断后执行
   3. do-while循环：`do{...} while(条件);`，先执行一次再判断，至少执行一次
   4. 循环控制：break（跳出当前循环）、continue（跳过本次循环，进入下一次）

#### 2.2.8 数组

数组：存储多个相同类型数据的连续内存空间，长度固定。

1. 声明与初始化：

   1. 静态初始化：`数据类型[] 数组名 = {元素1, 元素2, ...};`（如 int[] arr = {1,2,3};）
   2. 动态初始化：`数据类型[] 数组名 = new 数据类型[长度];`（如 int[] arr = new int[3];，元素默认初始化（整数0、浮点0.0、布尔false、引用null））
2. 访问数组：通过索引（从0开始）访问，格式：`数组名[索引]`，索引越界会抛出 ArrayIndexOutOfBoundsException
3. 数组属性：`数组名.length` 获取数组长度
4. 数组遍历：for循环、增强for循环（foreach，JDK5+）：
   `for(int num : arr) { // 遍历arr数组，将每个元素赋值给num ``    System.out.println(num); ``}`
5. 二维数组：数组的数组，声明格式：`数据类型[][] 数组名 = new 数据类型[行数][列数];` 或 静态初始化 `{ {1,2}, {3,4} }`

## 三、面向对象编程（OOP）

### 3.1 面向对象核心概念

对象：现实世界的实体，具有属性（数据）和方法（行为）；类：对象的抽象模板，定义对象的共同属性和方法。

关系：类 → 实例化 → 对象（一个类可以创建多个对象）

### 3.2 类与对象的创建

```java
// 定义类
class Person {
    // 属性（成员变量，声明在类中，方法外，有默认值）
    String name;
    int age;
  
    // 方法（成员方法，描述行为）
    public void eat() {
        System.out.println(name + "在吃饭");
    }
}

// 实例化对象
public class Test {
    public static void main(String[] args) {
        Person p = new Person(); // new关键字创建对象，分配内存
        p.name = "张三"; // 给属性赋值
        p.age = 20;
        p.eat(); // 调用方法，输出：张三在吃饭
    }
}
```

### 3.3 封装

封装：隐藏对象的内部细节，仅通过公共方法暴露对外接口，提高安全性和可维护性。

实现步骤：

1. 用private修饰成员变量（私有属性，外部无法直接访问）
2. 提供public的getter方法（获取属性值）和setter方法（设置属性值）

```java
class Person {
    private String name; // 私有属性
    private int age;
  
    // getter方法
    public String getName() {
        return name;
    }
  
    // setter方法
    public void setName(String name) {
        this.name = name; // this指代当前对象
    }
  
    public int getAge() {
        return age;
    }
  
    public void setAge(int age) {
        if(age > 0 && age < 150) { // 可以在setter中添加逻辑校验
            this.age = age;
        } else {
            System.out.println("年龄非法");
        }
    }
}
```

### 3.4 构造方法

构造方法：用于初始化对象的特殊方法，创建对象时自动调用。

特点：

1. 方法名与类名完全一致，无返回值类型（包括void）
2. 默认存在无参构造方法（若手动定义了构造方法，默认无参构造会失效）
3. 可以重载（多个构造方法，参数列表不同）

```java
class Person {
    private String name;
    private int age;
  
    // 无参构造
    public Person() {
        System.out.println("无参构造被调用");
    }
  
    // 带参构造（重载）
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
        System.out.println("带参构造被调用");
    }
}

// 测试
Person p1 = new Person(); // 调用无参构造
Person p2 = new Person("李四", 25); // 调用带参构造
```

### 3.5 继承

继承：子类继承父类的属性和方法，实现代码复用，提高开发效率。

特点：

1. 用extends关键字：`class 子类 extends 父类 {}`
2. Java单继承（一个子类只能有一个直接父类），但支持多层继承（如 A → B → C）
3. 子类继承父类的非private属性和方法，不能继承构造方法
4. super关键字：指代父类对象，可用于调用父类的构造方法（super()，必须在子类构造方法第一行）、属性、方法

```java
// 父类
class Animal {
    String name;
    public void eat() {
        System.out.println(name + "在吃东西");
    }
}

// 子类
class Dog extends Animal {
    // 子类特有方法
    public void bark() {
        System.out.println(name + "在叫");
    }
}

// 测试
Dog dog = new Dog();
dog.name = "旺财";
dog.eat(); // 继承父类方法，输出：旺财在吃东西
dog.bark(); // 子类特有方法，输出：旺财在叫
```

### 3.6 多态

多态：同一方法调用，根据对象的实际类型不同，执行不同的逻辑，提高代码灵活性。

实现条件：

1. 存在继承关系（子类继承父类）
2. 子类重写（Override）父类方法（方法名、参数列表、返回值类型完全一致，父类方法不能是private）
3. 父类引用指向子类对象（`父类类型 变量名 = new 子类类型();`）

```java
// 父类
class Animal {
    public void eat() {
        System.out.println("动物在吃东西");
    }
}

// 子类1
class Dog extends Animal {
    @Override // 重写注解，校验重写是否正确
    public void eat() {
        System.out.println("狗在吃骨头");
    }
}

// 子类2
class Cat extends Animal {
    @Override
    public void eat() {
        System.out.println("猫在吃鱼");
    }
}

// 测试
public class Test {
    public static void main(String[] args) {
        Animal a1 = new Dog(); // 父类引用指向Dog对象
        Animal a2 = new Cat(); // 父类引用指向Cat对象
        a1.eat(); // 执行Dog的eat方法，输出：狗在吃骨头
        a2.eat(); // 执行Cat的eat方法，输出：猫在吃鱼
    }
}
```

多态注意事项：父类引用只能调用父类中定义的方法（包括子类重写的方法），不能直接调用子类特有方法（需强制类型转换为子类类型）。

### 3.7 抽象类与接口

#### 3.7.1 抽象类（abstract class）

抽象类：包含抽象方法的类，不能实例化，只能被继承。

抽象方法：用abstract修饰，无方法体，必须由子类重写。

```java
abstract class Shape { // 抽象类
    abstract void draw(); // 抽象方法（无方法体）
  
    public void getArea() { // 普通方法
        System.out.println("计算面积");
    }
}

class Circle extends Shape {
    @Override
    void draw() { // 子类必须重写抽象方法
        System.out.println("画圆形");
    }
}

// Shape s = new Shape(); // 错误，抽象类不能实例化
Shape s = new Circle(); // 正确，父类引用指向子类对象
s.draw(); // 输出：画圆形
```

#### 3.7.2 接口（interface）

接口：抽象方法的集合（JDK8+后支持默认方法、静态方法），用于定义规范，不关注实现。

特点：

1. 用interface关键字定义：`interface 接口名 {}`
2. 接口中的方法默认是public abstract（可省略），变量默认是public static final（常量）
3. 类实现接口用implements关键字，一个类可以实现多个接口（解决Java单继承问题）
4. 实现类必须重写接口中所有抽象方法（若实现类是抽象类，可不用）

```java
// 定义接口
interface Swim {
    void swim(); // 抽象方法
}

interface Fly {
    void fly();
}

// 类实现多个接口
class Bird implements Fly, Swim {
    @Override
    public void fly() {
        System.out.println("鸟在飞");
    }
  
    @Override
    public void swim() {
        System.out.println("鸟在游");
    }
}
```

#### 3.7.3 抽象类与接口的区别

| 维度                          | 抽象类                                       | 接口                                          |
| ----------------------------- | -------------------------------------------- | --------------------------------------------- |
| ----------------------------- |                                              |                                               |
| 继承/实现                     | 单继承                                       | 多实现                                        |
| -                             | -                                            | -                                             |
| 方法类型                      | 可包含抽象方法、普通方法、静态方法、默认方法 | JDK8前仅抽象方法；JDK8+支持默认方法、静态方法 |
| 变量类型                      | 可包含普通变量、常量                         | 仅常量（public static final）                 |
| 实例化                        | 不能直接实例化                               | 不能实例化                                    |
| 核心作用                      | 代码复用（继承父类共性）                     | 定义规范（多实现扩展功能）                    |

### 3.8 内部类

内部类：定义在另一个类内部的类，分为成员内部类、局部内部类、匿名内部类、静态内部类。

#### 3.8.1 匿名内部类（常用）

匿名内部类：没有类名的内部类，只能使用一次，通常用于快速实现接口或继承抽象类。

```java
interface Run {
    void run();
}

public class Test {
    public static void main(String[] args) {
        // 匿名内部类实现Run接口
        Run run = new Run() {
            @Override
            public void run() {
                System.out.println("快速跑步");
            }
        };
        run.run(); // 输出：快速跑步
    }
}
```

## 四、集合框架

### 4.1 集合概述

集合：用于存储多个对象（引用数据类型），长度可变，提供丰富的操作方法（增删改查、排序等），替代数组的局限性。

集合框架核心接口：Collection（单列集合）、Map（双列集合，键值对）

### 4.2 Collection 接口

Collection 是单列集合的顶层接口，常用子接口：List（有序、可重复）、Set（无序、不可重复）

#### 4.2.1 List 接口

List 特点：有序（存储顺序与取出顺序一致）、可重复，支持索引访问。

常用实现类：

1. ArrayList：底层是动态数组，查询快、增删慢（末尾增删快），线程不安全，效率高
2. LinkedList：底层是双向链表，查询慢、增删快，线程不安全，效率高
3. Vector：底层是动态数组，线程安全，效率低（已过时，推荐用Collections.synchronizedList替代）

常用方法：add()、get()、set()、remove()、size()、isEmpty() 等

```java
List<String> list = new ArrayList<>();
list.add("张三");
list.add("李四");
list.add("张三"); // 可重复
System.out.println(list.get(0)); // 按索引获取，输出：张三
list.remove(1); // 删除索引1的元素（李四）
for(String s : list) {
    System.out.println(s); // 输出：张三、张三（有序）
}
```

#### 4.2.2 Set 接口

Set 特点：无序（存储顺序与取出顺序不一定一致）、不可重复（元素需重写equals()和hashCode()方法保证唯一性）。

常用实现类：

1. HashSet：底层是哈希表（数组+链表/红黑树），查询和增删效率高，无序
2. TreeSet：底层是红黑树，可对元素自然排序（如整数升序、字符串字典序）或自定义排序，有序

```java
Set<String> set = new HashSet<>();
set.add("张三");
set.add("李四");
set.add("张三"); // 重复元素，添加失败
System.out.println(set); // 输出：[张三, 李四]（无序）

// TreeSet 自然排序
Set<Integer> treeSet = new TreeSet<>();
treeSet.add(3);
treeSet.add(1);
treeSet.add(2);
System.out.println(treeSet); // 输出：[1, 2, 3]（有序）
```

### 4.3 Map 接口

Map 是双列集合的顶层接口，存储键值对（key-value），key 唯一（不可重复），value 可重复，key 与 value 一一对应。

常用实现类：

1. HashMap：底层是哈希表，查询和增删效率高，无序，线程不安全，key 允许为null（仅一个）
2. TreeMap：底层是红黑树，可对key自然排序或自定义排序，有序
3. Hashtable：底层是哈希表，线程安全，效率低，key 和 value 不允许为null（已过时）

常用方法：put(key,value)、get(key)、remove(key)、containsKey(key)、keySet()（获取所有key）、entrySet()（获取所有键值对）等

```java
Map<String, Integer> map = new HashMap<>();
map.put("张三", 20);
map.put("李四", 25);
map.put("张三", 22); // key重复，覆盖value
System.out.println(map.get("张三")); // 输出：22

// 遍历方式1：遍历key，再获取value
Set<String> keys = map.keySet();
for(String key : keys) {
    System.out.println(key + ":" + map.get(key));
}

// 遍历方式2：遍历键值对
Set<Map.Entry<String, Integer>> entries = map.entrySet();
for(Map.Entry<String, Integer> entry : entries) {
    System.out.println(entry.getKey() + ":" + entry.getValue());
}
```

### 4.4 集合工具类 Collections

Collections 是操作集合的工具类，提供静态方法：

* 排序：Collections.sort(list)（List集合排序）
* 查找：Collections.binarySearch(list, 元素)（二分查找，需先排序）
* 线程安全：Collections.synchronizedList(list)（将非线程安全的List转为线程安全）
* 其他：Collections.max(collection)（获取最大值）、Collections.min(collection)（获取最小值）

## 五、IO 流

### 5.1 IO 概述

IO（Input/Output）：输入输出，用于程序与外部设备（文件、键盘、网络等）之间的数据传输。

IO 流分类：

1. 按流向分：输入流（读取数据到程序）、输出流（从程序写出数据）
2. 按数据类型分：字节流（传输字节，可处理任意文件，如图片、视频）、字符流（传输字符，仅处理文本文件，如.txt、.java）

核心基类：

* 字节流：InputStream（输入）、OutputStream（输出）
* 字符流：Reader（输入）、Writer（输出）

### 5.2 字节流

#### 5.2.1 FileInputStream（文件字节输入流）

作用：从文件中读取字节数据。

```java
// 读取文件内容
public class Test {
    public static void main(String[] args) throws IOException {
        // 1. 创建流对象（关联文件路径）
        FileInputStream fis = new FileInputStream("test.txt");
  
        // 2. 读取数据（一次读1个字节）
        int b;
        while((b = fis.read()) != -1) { // read()返回读取的字节，无数据返回-1
            System.out.print((char)b); // 转为字符输出
        }
  
        // 3. 关闭流（释放资源，必须执行）
        fis.close();
    }
}
```

#### 5.2.2 FileOutputStream（文件字节输出流）

作用：将字节数据写入文件。

```java
// 写入数据到文件
public class Test {
    public static void main(String[] args) throws IOException {
        // 创建流对象，true表示追加写入（不覆盖原有内容）
        FileOutputStream fos = new FileOutputStream("test.txt", true);
  
        // 写入数据（字符串转字节数组）
        String content = "Hello, IO!";
        fos.write(content.getBytes());
  
        // 关闭流
        fos.close();
    }
}
```

### 5.3 字符流

字符流 = 字节流 + 编码表（如UTF-8、GBK），解决字节流读取文本文件时的中文乱码问题。

#### 5.3.1 FileReader（文件字符输入流）

```java
public class Test {
    public static void main(String[] args) throws IOException {
        FileReader fr = new FileReader("test.txt");
  
        int ch;
        while((ch = fr.read()) != -1) {
            System.out.print((char)ch); // 直接读取字符，无乱码
        }
  
        fr.close();
    }
}
```

#### 5.3.2 FileWriter（文件字符输出流）

```java
public class Test {
    public static void main(String[] args) throws IOException {
        FileWriter fw = new FileWriter("test.txt");
  
        fw.write("你好，Java！"); // 直接写入字符
        fw.flush(); // 字符流需手动刷新（将缓冲区数据写入文件）
        fw.close(); // close()会自动调用flush()
    }
}
```

### 5.4 缓冲流

缓冲流（包装流）：基于基本流，增加缓冲区（内存区域），减少IO操作次数，提高读写效率。

常用缓冲流：

* 字节缓冲流：BufferedInputStream、BufferedOutputStream
* 字符缓冲流：BufferedReader、BufferedWriter（提供readLine()读取一行、newLine()换行等便捷方法）

```java
// 缓冲字符流读取文件
public class Test {
    public static void main(String[] args) throws IOException {
        // 包装FileReader
        BufferedReader br = new BufferedReader(new FileReader("test.txt"));
  
        String line;
        while((line = br.readLine()) != null) { // 读取一行，无数据返回null
            System.out.println(line);
        }
  
        br.close();
    }
}
```

### 5.5 资源自动关闭（try-with-resources）

JDK7+ 新增，自动关闭实现AutoCloseable接口的资源（如IO流），无需手动调用close()。

```java
public class Test {
    public static void main(String[] args) {
        // 资源声明在try括号中，自动关闭
        try(BufferedReader br = new BufferedReader(new FileReader("test.txt"))) {
            String line;
            while((line = br.readLine()) != null) {
                System.out.println(line);
            }
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

## 六、多线程

### 6.1 线程概述

进程：正在运行的程序，是操作系统资源分配的基本单位。

线程：进程中的一个执行单元，是CPU调度的基本单位，一个进程可以包含多个线程（多线程）。

多线程优势：提高程序执行效率（如同时处理多个任务）、充分利用CPU资源。

### 6.2 线程的创建方式

#### 6.2.1 继承 Thread 类

```java
// 1. 自定义线程类继承Thread
class MyThread extends Thread {
    // 2. 重写run()方法（线程执行的任务）
    @Override
    public void run() {
        for(int i = 0; i < 5; i++) {
            System.out.println(Thread.currentThread().getName() + ":" + i);
        }
    }
}

// 测试
public class Test {
    public static void main(String[] args) {
        // 3. 创建线程对象
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();
  
        // 4. 启动线程（调用start()，底层调用run()）
        t1.start();
        t2.start();
    }
}
```

#### 6.2.2 实现 Runnable 接口

推荐使用（避免单继承限制，可实现多个接口）：

```java
// 1. 自定义类实现Runnable
class MyRunnable implements Runnable {
    // 2. 重写run()方法
    @Override
    public void run() {
        for(int i = 0; i < 5; i++) {
            System.out.println(Thread.currentThread().getName() + ":" + i);
        }
    }
}

// 测试
public class Test {
    public static void main(String[] args) {
        // 3. 创建Runnable实现类对象
        MyRunnable mr = new MyRunnable();
  
        // 4. 创建Thread对象，传入Runnable对象
        Thread t1 = new Thread(mr);
        Thread t2 = new Thread(mr);
  
        // 5. 启动线程
        t1.start();
        t2.start();
    }
}
```

### 6.3 线程状态

线程生命周期的5种状态：新建（New）→ 就绪（Runnable）→ 运行（Running）→ 阻塞（Blocked）→ 死亡（Terminated）

* 新建：创建线程对象（new Thread()），未启动
* 就绪：调用start()后，线程进入就绪队列，等待CPU调度
* 运行：CPU调度线程，执行run()方法中的任务
* 阻塞：线程暂停执行（如sleep()、wait()、同步锁等待），解除阻塞后回到就绪状态
* 死亡：run()方法执行完毕或调用stop()（已过时），线程终止

### 6.4 线程控制方法

* sleep(long millis)：线程休眠指定毫秒数，期间释放CPU，不释放锁
* join()：等待该线程执行完毕后，其他线程再继续执行
* setDaemon(boolean on)：设置为守护线程（如垃圾回收线程），当所有非守护线程结束，守护线程自动结束
* setPriority(int newPriority)：设置线程优先级（1-10，默认5），优先级高的线程更易被CPU调度

### 6.5 线程安全问题

线程安全：多个线程同时操作共享资源时，可能出现数据错误（如并发修改共享变量）。

解决方式：同步机制（保证同一时间只有一个线程操作共享资源）

#### 6.5.1 同步代码块

```java
synchronized(同步锁对象) {
    // 同步代码（操作共享资源的代码）
}
```

#### 6.5.2 同步方法

```java
// 成员方法：同步锁是this（当前对象）
public synchronized void method() {
    // 同步代码
}

// 静态方法：同步锁是类的字节码对象（类名.class）
public static synchronized void method() {
    // 同步代码
}
```

#### 6.5.3 Lock 锁（JDK5+）

Lock 是接口，常用实现类 ReentrantLock，手动加锁和释放锁，灵活性更高。

```java
class MyRunnable implements Runnable {
    private Lock lock = new ReentrantLock(); // 创建Lock对象
  
    @Override
    public void run() {
        lock.lock(); // 加锁
        try {
            // 操作共享资源
            for(int i = 0; i < 5; i++) {
                System.out.println(Thread.currentThread().getName() + ":" + i);
            }
        } finally {
            lock.unlock(); // 释放锁（必须在finally中，确保锁一定释放）
        }
    }
}
```

## 七、异常处理

### 7.1 异常概述

异常：程序运行时出现的错误（如空指针、数组越界、文件找不到等），会导致程序中断。

异常体系：顶层类是Throwable，分为Error（错误，如内存溢出，无法通过代码处理）和Exception（异常，可通过代码处理）。

Exception 分类：

1. 编译时异常（检查性异常）：编译时必须处理（如IOException、SQLException），否则无法通过编译
2. 运行时异常（非检查性异常）：编译时无需处理，运行时才可能出现（如NullPointerException、ArrayIndexOutOfBoundsException）

### 7.2 异常处理方式

#### 7.2.1 try-catch 捕获异常

```java
try {
    // 可能出现异常的代码
} catch (异常类型1 异常变量名) {
    // 处理异常1的逻辑
} catch (异常类型2 异常变量名) {
    // 处理异常2的逻辑
} finally {
    // 无论是否出现异常，都会执行的代码（如释放资源）
}
```

#### 7.2.2 throws 声明异常

在方法声明处使用throws，将异常抛给调用者，由调用者处理。

```java
public static void readFile() throws IOException { // 声明异常
    FileReader fr = new FileReader("test.txt");
    fr.close();
}

// 调用者处理异常
public static void main(String[] args) {
    try {
        readFile();
    } catch (IOException e) {
        e.printStackTrace(); // 打印异常信息（堆栈跟踪）
    }
}
```

#### 7.2.3 throw 抛出异常

手动抛出异常对象（通常用于自定义异常场景）。

```java
public static void checkAge(int age) {
    if(age < 0 || age > 150) {
        throw new IllegalArgumentException("年龄非法"); // 手动抛出运行时异常
    }
}
```

### 7.3 自定义异常

自定义异常：继承Exception（编译时异常）或RuntimeException（运行时异常），重写构造方法。

```java
// 自定义编译时异常
class AgeException extends Exception {
    public AgeException() {}
    public AgeException(String message) {
        super(message); // 调用父类构造，传递异常信息
    }
}

// 使用自定义异常
public static void checkAge(int age) throws AgeException {
    if(age < 0 || age > 150) {
        throw new AgeException("年龄非法");
    }
}
```

## 八、常用类

### 8.1 String 类

String 特点：不可变字符序列（底层是char数组，被final修饰），字符串常量池（缓存重复字符串，节省内存）。

常用方法：

* length()：获取字符串长度
* equals()：比较字符串内容（区分大小写），== 比较地址
* equalsIgnoreCase()：忽略大小写比较内容
* concat()：拼接字符串（等价于+）
* substring(int beginIndex, int endIndex)：截取字符串（左闭右开）
* replace(CharSequence old, CharSequence newStr)：替换字符串中的字符或子串
* split(String regex)：根据正则表达式拆分字符串，返回字符串数组
* trim()：去除字符串首尾空白字符（JDK11+可用strip()，支持更多空白字符）
* indexOf(String str)：查找子串首次出现的索引，未找到返回-1
* lastIndexOf(String str)：查找子串最后出现的索引
* toLowerCase()：将字符串转为小写
* toUpperCase()：将字符串转为大写

### 8.2 StringBuffer 与 StringBuilder 类

两者均为可变字符序列（底层是可扩容的char数组），用于频繁修改字符串场景（如拼接、替换），效率高于String（避免创建大量临时字符串）。

核心区别：

* StringBuffer：线程安全，方法加了synchronized修饰，效率较低
* StringBuilder：线程不安全，效率较高（推荐单线程环境使用，是StringBuffer的替代者）

常用方法（两者用法基本一致）：

* append(任意类型)：追加内容到末尾（核心方法）
* insert(int offset, 任意类型)：在指定索引处插入内容
* replace(int start, int end, String str)：替换指定范围的子串（左闭右开）
* delete(int start, int end)：删除指定范围的子串
* reverse()：反转字符序列
* toString()：转为不可变的String对象

```java
// StringBuilder示例
StringBuilder sb = new StringBuilder("Hello");
sb.append(" Java"); // 追加：Hello Java
sb.insert(5, ","); // 插入：Hello, Java
sb.reverse(); // 反转：avaJ ,olleH
System.out.println(sb.toString()); // 转为String输出
```

### 8.3 包装类

包装类是基本数据类型的“包装器”，将基本类型转为引用类型，便于在集合中存储（集合只能存引用类型），并提供丰富的操作方法。

8种基本类型对应的包装类：

* byte → Byte、short → Short、int → Integer、long → Long
* float → Float、double → Double、char → Character、boolean → Boolean

核心特性：自动装箱与自动拆箱（JDK5+）

* 自动装箱：基本类型 → 包装类（如 int → Integer）
* 自动拆箱：包装类 → 基本类型（如 Integer → int）

```java
// 自动装箱
Integer num1 = 10; // 等价于 Integer num1 = Integer.valueOf(10);
// 自动拆箱
int num2 = num1; // 等价于 int num2 = num1.intValue();
// 集合中使用（必须用包装类）
List<Integer> list = new ArrayList<>();
list.add(20); // 自动装箱为Integer
```

常用方法（以Integer为例）：

* parseInt(String s)：将字符串转为int（核心方法，如 Integer.parseInt("123") → 123）
* valueOf(int i)：返回Integer对象（缓存-128~127范围内的对象，复用内存）
* toString()：将Integer转为String
* compareTo(Integer anotherInteger)：比较两个Integer的大小

### 8.4 日期时间类（JDK8+）

JDK8之前的Date、Calendar类存在线程不安全、API设计混乱等问题，JDK8新增java.time包，提供线程安全、易用的日期时间类。

核心类：

#### 8.4.1 LocalDate（日期）

仅包含年、月、日，无时间信息，线程安全。

```java
// 获取当前日期
LocalDate nowDate = LocalDate.now();
System.out.println(nowDate); // 输出格式：2025-12-28
// 构造指定日期
LocalDate date = LocalDate.of(2025, 12, 28);
// 获取年、月、日
int year = date.getYear();
int month = date.getMonthValue(); // 1-12
int day = date.getDayOfMonth();
// 日期计算
LocalDate nextWeek = date.plusWeeks(1); // 加1周
LocalDate lastMonth = date.minusMonths(1); // 减1月
```

#### 8.4.2 LocalTime（时间）

仅包含时、分、秒、纳秒，无日期信息，线程安全。

```java
LocalTime nowTime = LocalTime.now();
System.out.println(nowTime); // 输出格式：15:30:45.123
// 构造指定时间
LocalTime time = LocalTime.of(15, 30, 45);
// 时间计算
LocalTime later = time.plusHours(2); // 加2小时
```

#### 8.4.3 LocalDateTime（日期+时间）

包含年、月、日、时、分、秒，最常用，线程安全。

```java
// 获取当前日期时间
LocalDateTime now = LocalDateTime.now();
// 格式化（日期时间 ↔ 字符串）
DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
String nowStr = now.format(formatter); // 转为字符串：2025-12-28 15:35:20
// 字符串转为LocalDateTime
LocalDateTime parseDate = LocalDateTime.parse("2025-12-28 15:35:20", formatter);
```

### 8.5 Math 类

Math类是数学工具类，所有方法都是静态方法，无需创建对象，用于执行基本数学运算。

常用方法：

* abs(int a)：求绝对值（如 Math.abs(-5) → 5）
* max(int a, int b)：求两数最大值（Math.max(3,7) →7）
* min(int a, int b)：求两数最小值
* random()：生成0.0~1.0之间的随机double值（含0.0，不含1.0）
* sqrt(double a)：求平方根（Math.sqrt(16) →4.0）
* pow(double a, double b)：求a的b次方（Math.pow(2,3) →8.0）
* round(double a)：四舍五入（Math.round(3.6) →4，返回long类型）

```java
// 生成1-100之间的随机整数
int randomNum = (int)(Math.random() * 100) + 1;
```

### 8.6 Arrays 类

Arrays是数组工具类，提供静态方法用于数组的排序、查找、填充、比较等操作。

常用方法：

* sort(数组)：对数组排序（基本类型升序，引用类型需实现Comparable接口）
* binarySearch(数组, 查找元素)：二分查找元素，返回索引（数组需先排序，未找到返回负数）
* fill(数组, 填充值)：将数组所有元素填充为指定值
* toString(数组)：将数组转为字符串（便于打印，如 Arrays.toString(new int[]{1,2,3}) → "[1, 2, 3]"）
* equals(数组1, 数组2)：比较两个数组的元素是否完全一致

```java
int[] arr = {3,1,2,5,4};
Arrays.sort(arr); // 排序后：[1,2,3,4,5]

Arrays.fill(arr, 0); // 填充后：[0,0,0,0,0]
System.out.println(Arrays.toString(arr)); // 输出：[0, 0, 0, 0, 0]
```

# Spring 核心概念总结

## 一、Spring 框架概述

Spring 是一个轻量级、开源的 Java EE 应用框架，核心定位是“简化 Java 开发”。它通过核心的 IOC 和 AOP 机制，解决了传统 Java 开发中代码耦合度高、配置繁琐等问题，提供了一站式的企业级开发解决方案（涵盖数据访问、Web 开发、事务管理、安全等多个领域）。

核心优势：

* 轻量级：核心包体积小，无强制依赖，运行开销低
* 松耦合：通过 IOC 容器管理对象依赖，降低组件间耦合
* 面向切面：AOP 机制支持横切逻辑（如日志、事务）的统一处理，不侵入业务代码
* 一站式：提供 Spring MVC（Web）、Spring JDBC（数据访问）、Spring Security（安全）等模块，无缝整合
* 生态丰富：可与 MyBatis、Hibernate、Redis 等主流框架/中间件快速集成

## 二、核心概念：IOC（控制反转）

### 2.1 定义与核心思想

IOC（Inversion of Control，控制反转）是 Spring 最核心的思想，本质是 **对象创建权的反转** ：

* 传统开发：开发者主动通过 `new` 关键字创建对象，并管理对象间的依赖关系（如 Service 依赖 Dao 时，需在 Service 中手动创建 Dao 对象）
* Spring IOC：将对象的创建、初始化、依赖管理等控制权交给 Spring 容器，开发者仅需通过配置或注解声明对象，由容器负责“按需提供”对象

核心价值：解放开发者的对象管理工作，降低组件间的耦合度，便于代码维护和扩展。

### 2.2 IOC 容器

IOC 容器是 Spring 实现 IOC 思想的核心载体，本质是一个“对象工厂”，负责：

1. 加载并解析配置（XML/注解）
2. 创建并初始化对象（称为 Bean）
3. 管理 Bean 的生命周期（创建 → 初始化 → 销毁）
4. 维护 Bean 间的依赖关系

Spring 核心容器接口：

* BeanFactory：最基础的容器接口，提供 Bean 的获取、创建等核心功能，采用“懒加载”（获取 Bean 时才创建）
* ApplicationContext：BeanFactory 的子接口，增强了功能（如国际化、事件发布、资源加载），采用“预加载”（容器初始化时就创建所有 Bean），是开发中最常用的容器类型（常用实现类：ClassPathXmlApplicationContext、AnnotationConfigApplicationContext）

## 三、核心概念：DI（依赖注入）

### 3.1 定义与与 IOC 的关系

DI（Dependency Injection，依赖注入）是 IOC 思想的 **具体实现方式** ：容器在创建对象时，自动将该对象所依赖的其他对象（依赖项）注入到其中，无需开发者手动设置。

关系：IOC 是核心思想（“反转控制权”），DI 是实现手段（“如何反转”）—— 通过依赖注入，实现了对象依赖关系的控制权反转。

### 3.2 依赖注入的 3 种常用方式

#### 3.2.1 构造器注入

通过对象的构造方法，将依赖项作为参数传入，容器在创建对象时调用该构造方法完成注入。

```java
// 1. 服务层依赖数据访问层
public class UserService {
    private UserDao userDao;
  
    // 2. 构造方法接收依赖项
    public UserService(UserDao userDao) {
        this.userDao = userDao;
    }
  
    // 业务方法
    public void getUser() {
        userDao.queryUser();
    }
}

// 3. 配置类（或 XML）声明 Bean，容器自动注入依赖
@Configuration
public class SpringConfig {
    @Bean
    public UserDao userDao() {
        return new UserDaoImpl();
    }
  
    @Bean
    // 容器自动将 userDao 注入到 UserService 构造器
    public UserService userService(UserDao userDao) {
        return new UserService(userDao);
    }
}
```

特点：强制依赖（必须传入依赖项才能创建对象），适合依赖项不可缺少的场景。

#### 3.2.2 Setter 注入

通过对象的 Setter 方法设置依赖项，容器在创建对象后，调用对应的 Setter 方法完成注入。

```java
public class UserService {
    private UserDao userDao;
  
    // 1. 提供 Setter 方法
    public void setUserDao(UserDao userDao) {
        this.userDao = userDao;
    }
  
    public void getUser() {
        userDao.queryUser();
    }
}

// 2. XML 配置方式（也可通过 @Autowired + @Setter 注解）
<bean id="userDao" class="com.dao.UserDaoImpl"/>
<bean id="userService" class="com.service.UserService">
    <property name="userDao" ref="userDao"/> <!-- 调用 setUserDao 注入 -->
</bean>
```

特点：可选依赖（无需依赖项也可创建对象），灵活性高，适合依赖项可动态变化的场景。

#### 3.2.3 注解注入（最常用）

通过注解（如 `@Autowired`、`@Resource`）直接标记依赖项，容器自动扫描并注入，简化配置。

```java
// 1. 开启组件扫描（XML：<context:component-scan base-package="com"/> 或 注解：@ComponentScan）
@Configuration
@ComponentScan("com")
public class SpringConfig {}

// 2. 数据访问层：标记为 Bean（@Repository 表示持久层组件）
@Repository
public class UserDaoImpl implements UserDao {
    @Override
    public void queryUser() {
        System.out.println("查询用户");
    }
}

// 3. 服务层：通过 @Autowired 注入依赖（自动按类型匹配）
@Service
public class UserService {
    // 方式1：属性注入（最简单）
    @Autowired
    private UserDao userDao;
  
    // 方式2：构造器注入（推荐，Spring 4.3+ 可省略 @Autowired）
    // public UserService(UserDao userDao) {
    //     this.userDao = userDao;
    // }
  
    public void getUser() {
        userDao.queryUser();
    }
}
```

关键注解说明：

* @Component：通用组件注解，标记类为 Spring 管理的 Bean
* @Repository：专门用于持久层（Dao）的组件注解
* @Service：专门用于服务层（Service）的组件注解
* @Controller：专门用于控制层（Controller）的组件注解
* @Autowired：Spring 提供的注解，按**类型**匹配依赖（默认要求依赖项必须存在，可通过 required=false 设为可选）
* @Resource：JDK 提供的注解，默认按**名称**匹配依赖，可指定 name 属性

## 四、核心概念：AOP（面向切面编程）

### 4.1 定义与核心思想

AOP（Aspect-Oriented Programming，面向切面编程）是一种“横向编程”思想，用于解决传统“纵向继承”无法解决的横切逻辑问题（如日志记录、事务管理、权限校验等）。

核心思想：将横切逻辑（不属于核心业务，但多个业务都需要的逻辑）抽取为“切面”，通过动态代理技术，在不修改核心业务代码的前提下，将切面逻辑“织入”到核心业务的指定位置（如方法执行前、执行后）。

价值：分离核心业务与横切逻辑，降低代码冗余，提高横切逻辑的复用性和可维护性。

### 4.2 AOP 核心术语

* 切面（Aspect）：抽取的横切逻辑类（如日志切面、事务切面），包含通知和切入点
* 通知（Advice）：切面中的具体逻辑方法，定义了“何时”执行横切逻辑，分为 5 种类型：
  * 前置通知（@Before）：目标方法执行前执行
  * 后置通知（@After）：目标方法执行后执行（无论是否异常）
  * 返回通知（@AfterReturning）：目标方法正常返回后执行
  * 异常通知（@AfterThrowing）：目标方法抛出异常后执行
  * 环绕通知（@Around）：包裹目标方法，可在执行前后自定义逻辑（功能最强）
* 切入点（Pointcut）：定义“哪些方法”需要织入切面逻辑，通过切入点表达式描述（如匹配所有 Service 层的方法）
* 目标对象（Target）：被切面织入的核心业务对象（如 UserService）
* 代理对象（Proxy）：Spring 通过动态代理创建的目标对象代理，切面逻辑通过代理对象执行
* 织入（Weaving）：将切面逻辑融入目标对象的过程（Spring 自动完成，无需手动干预）

### 4.3 AOP 实现示例（注解方式）

```java
// 1. 开启 AOP 自动代理（@EnableAspectJAutoProxy）
@Configuration
@ComponentScan("com")
@EnableAspectJAutoProxy
public class SpringConfig {}

// 2. 核心业务类（目标对象）
@Service
public class UserService {
    public void addUser() {
        System.out.println("新增用户（核心业务）");
        // int i = 1/0; // 测试异常通知
    }
}

// 3. 定义切面类（@Aspect 标记，@Component 交给 Spring 管理）
@Aspect
@Component
public class LogAspect {
    // 切入点表达式：匹配 com.service 包下所有类的所有方法
    @Pointcut("execution(* com.service.*.*(..))")
    public void servicePointcut() {} // 切入点签名（无实际逻辑）
  
    // 前置通知：在切入点方法执行前执行
    @Before("servicePointcut()")
    public void beforeAdvice() {
        System.out.println("前置通知：记录方法执行开始时间");
    }
  
    // 返回通知：在切入点方法正常返回后执行
    @AfterReturning("servicePointcut()")
    public void afterReturningAdvice() {
        System.out.println("返回通知：记录方法执行成功");
    }
  
    // 环绕通知：包裹切入点方法
    @Around("servicePointcut()")
    public void aroundAdvice(ProceedingJoinPoint joinPoint) throws Throwable {
        System.out.println("环绕通知：方法执行前增强");
        joinPoint.proceed(); // 执行目标方法
        System.out.println("环绕通知：方法执行后增强");
    }
}
```

切入点表达式语法（核心）：

execution(访问修饰符 返回值类型 包名.类名.方法名(参数类型))

* *：通配符（如 * 表示任意返回值类型、任意方法名）
* ..：通配符（如包名中 .. 表示任意子包；参数中 .. 表示任意参数）
* 示例：
  * execution(* com.service.UserService.addUser(..))：匹配 UserService 的 addUser 方法（任意参数）
  * execution(* com.service.*.*(..))：匹配 com.service 包下所有类的所有方法
  * execution(public int com.service.*.*(String))：匹配 com.service 包下返回值为 int、参数为 String 的公共方法

## 五、核心概念：Bean

### 5.1 Bean 的定义

Bean 是 Spring 容器管理的对象，本质是 Java 类的实例，但由容器负责创建、初始化、依赖注入和销毁，是 Spring 应用的核心组件。

Bean 与普通 Java 对象的区别：普通对象由开发者 `new` 创建，Bean 由 Spring 容器创建和管理。

### 5.2 Bean 的作用域

Bean 的作用域定义了 Bean 实例的生命周期范围（即容器中该 Bean 的实例数量），Spring 提供 6 种常用作用域：

| 作用域                                                                                                           | 说明                                                           | 适用场景                              |
| ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------- |
| ---------------------------------------------------------------------------------------------------------------- |                                                                |                                       |
| singleton（单例）                                                                                                | 默认作用域，容器中仅存在一个 Bean 实例，所有请求共享该实例     | 无状态组件（如 Service、Dao）         |
| -                                                                                                                | -                                                              | -                                     |
| prototype（多例）                                                                                                | 每次请求（getBean() 或注入）都会创建一个新的 Bean 实例         | 有状态组件（如 Controller、视图对象） |
| request（请求）                                                                                                  | Web 应用中，每个 HTTP 请求对应一个 Bean 实例，请求结束后销毁   | Web 层请求相关组件                    |
| session（会话）                                                                                                  | Web 应用中，每个用户会话对应一个 Bean 实例，会话结束后销毁     | 用户会话相关组件（如购物车）          |
| application（应用）                                                                                              | Web 应用中，整个应用生命周期内仅一个 Bean 实例，共享于所有请求 | 应用级全局组件                        |
| websocket（WebSocket）                                                                                           | WebSocket 会话对应一个 Bean 实例，会话结束后销毁               | WebSocket 通信相关组件                |

作用域设置方式：通过 `@Scope` 注解（如 `@Scope("prototype")`）或 XML 配置（`<bean scope="prototype"/>`）。

### 5.3 Bean 的生命周期

Spring Bean 的完整生命周期（以 singleton 为例）：

1. 实例化（Instantiation）：容器通过构造方法创建 Bean 实例（`new` 对象）
2. 属性注入（Populate）：容器将依赖项注入到 Bean 的属性中（如 @Autowired 注入）
3. 初始化（Initialization）：

   1. 执行 BeanNameAware 的 setBeanName() 方法（注入 Bean 的名称）
   2. 执行 BeanFactoryAware 的 setBeanFactory() 方法（注入 BeanFactory 容器）
   3. 执行 InitializingBean 的 afterPropertiesSet() 方法（属性注入完成后执行）
   4. 执行自定义初始化方法（通过 @PostConstruct 注解或 XML init-method 配置）
4. 使用（In Use）：Bean 实例可用（供开发者调用）
5. 销毁（Destruction）：

   1. 执行 DisposableBean 的 destroy() 方法
   2. 执行自定义销毁方法（通过 @PreDestroy 注解或 XML destroy-method 配置）
   3. 容器关闭时，Bean 实例被销毁（释放资源）

## 六、Spring 核心模块

Spring 框架采用模块化设计，核心模块相互协作，也可独立使用：

* Spring Core（核心容器）：提供 IOC 容器、Bean 管理等核心功能，是其他模块的基础
* Spring AOP：提供面向切面编程实现，支持横切逻辑处理
* Spring Context：基于 Core 模块，提供国际化、事件发布、资源加载等扩展功能
* Spring JDBC：简化 JDBC 操作，提供统一的异常处理和模板类（JdbcTemplate）
* Spring TX（事务管理）：提供声明式事务和编程式事务管理，支持多种事务管理器
* Spring Web：提供 Web 开发基础支持（如 Servlet 集成、文件上传），是 Spring MVC 的基础
* Spring MVC：基于 MVC 模式的 Web 框架，处理请求分发、视图渲染等

## 七、核心总结

Spring 框架的核心是 **IOC（控制反转）** 和  **AOP（面向切面编程）** ：

* IOC 通过容器管理 Bean 的创建和依赖，实现组件松耦合；DI 是 IOC 的具体实现方式，负责依赖项的自动注入
* AOP 抽取横切逻辑为切面，动态织入核心业务，实现核心业务与非核心业务的分离
* Bean 是 Spring 管理的核心组件，其作用域和生命周期由容器统一控制
* Spring 模块化设计和丰富的生态，使其成为 Java 企业级开发的首选框架

# Spring Boot 核心概念总结

## 一、Spring Boot 概述

Spring Boot 是基于 Spring 框架的快速开发脚手架，核心目标是  **简化 Spring 应用的初始化、配置和部署流程** 。它通过“约定优于配置”的设计理念，消除了大量繁琐的 XML 配置和依赖管理工作，让开发者能够快速搭建可运行的企业级应用。

核心优势：

* 快速启动：一键创建可运行的 Spring 应用，无需手动整合各类组件
* 约定优于配置：内置默认配置，减少手动配置成本，开发者可专注业务逻辑
* 嵌入式服务器：内置 Tomcat、Jetty 等服务器，无需单独部署 WAR 包
* starters 依赖：提供标准化的依赖组合，一键引入所需功能（如数据库访问、Web 开发）
* 自动配置：根据项目依赖自动配置 Spring 组件，无需手动编写配置类
* 易于监控：集成 Spring Boot Actuator，轻松实现应用监控和管理
* 无缝兼容 Spring 生态：完全基于 Spring 开发，可直接使用 Spring 所有核心功能（IOC、AOP 等）

## 二、核心概念：约定优于配置（Convention over Configuration）

“约定优于配置”是 Spring Boot 最核心的设计思想，旨在通过默认约定减少开发者的配置工作量。

核心逻辑：Spring Boot 定义了一套标准化的默认规则（约定），如果开发者遵循这些规则，就无需手动配置；如果需要自定义，只需在约定的基础上进行少量修改即可。

典型约定示例：

* 项目结构约定：

  * 主程序类（带 `@SpringBootApplication` 注解）必须放在项目根包下
  * 默认扫描路径：主程序类所在包及其子包（无需手动配置组件扫描）
  * 资源文件默认位置：`src/main/resources`（配置文件、静态资源等）
* 配置文件约定：

  * 默认配置文件名：`application.properties` 或 `application.yml`
  * 配置项前缀约定：不同 Starter 有固定的配置前缀（如数据库配置前缀 `spring.datasource.`）
* 依赖约定：Starter 依赖会自动引入相关的核心依赖（如 `spring-boot-starter-web` 自动引入 Spring MVC、Tomcat 等）

## 三、核心概念：自动配置（Auto-configuration）

自动配置是 Spring Boot 实现“简化配置”的核心机制，指 Spring Boot 会根据项目中引入的依赖（Jar 包），自动推断并配置所需的 Spring 组件（如 Bean、数据源、视图解析器等），无需开发者手动编写 `@Configuration` 和 `@Bean` 注解。

### 3.1 自动配置的实现原理

自动配置的核心是 `@SpringBootApplication` 注解，它是一个复合注解，包含三个关键注解：

```java
// 主程序类示例
@SpringBootApplication // 复合注解，核心入口
public class SpringBootDemoApplication {
    public static void main(String[] args) {
        // 启动 Spring Boot 应用，返回 Spring 容器
        SpringApplication.run(SpringBootDemoApplication.class, args);
    }
}
```

三个关键注解解析：

* `@SpringBootConfiguration`：本质是 `@Configuration`，标记当前类为配置类，允许通过 `@Bean` 注册组件
* `@ComponentScan`：自动扫描主程序类所在包及其子包下的 `@Component`、`@Service`、`@Controller` 等注解，将其注册为 Spring Bean
* `@EnableAutoConfiguration`：开启自动配置核心注解，触发 Spring Boot 的自动配置机制

### 3.2 @EnableAutoConfiguration 的工作流程

1. Spring Boot 启动时，`@EnableAutoConfiguration` 会通过 `SpringFactoriesLoader` 加载类路径下 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 文件中的所有自动配置类（如 `DataSourceAutoConfiguration`、`DispatcherServletAutoConfiguration` 等）
2. 每个自动配置类通过 `@Conditional` 系列注解（条件注解）判断是否需要生效（如 `@ConditionalOnClass` 检查是否存在指定类，`@ConditionalOnMissingBean` 检查是否缺失指定 Bean）
3. 若条件满足，自动配置类会通过 `@Bean` 注解自动注册所需的组件到 Spring 容器中

核心逻辑：“按需配置”—— 只有引入了对应的依赖，且满足条件，才会自动配置对应的组件。

### 3.3 自定义自动配置（覆盖默认配置）

Spring Boot 允许开发者通过以下方式覆盖默认自动配置，实现自定义需求：

* 自定义配置类：编写带有 `@Configuration` 的配置类，通过 `@Bean` 注册自定义组件（默认情况下，自定义 Bean 会覆盖自动配置的 Bean）
* 配置文件修改：在 `application.properties` 或 `application.yml` 中修改自动配置的默认参数（如修改服务器端口 `server.port=8081`）
* 使用 `@EnableAutoConfiguration(exclude={xxx.class})` 或 `@SpringBootApplication(exclude={xxx.class})` 排除不需要的自动配置类

```java
// 示例：排除默认的数据源自动配置，使用自定义数据源
@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
public class SpringBootDemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(SpringBootDemoApplication.class, args);
    }
  
    // 自定义数据源 Bean
    @Bean
    public DataSource customDataSource() {
        DruidDataSource dataSource = new DruidDataSource();
        dataSource.setUrl("jdbc:mysql://localhost:3306/test");
        dataSource.setUsername("root");
        dataSource.setPassword("123456");
        return dataSource;
    }
}
```

## 四、核心概念：Starter 起步依赖

Starter（起步依赖）是 Spring Boot 提供的标准化依赖组合，它将某一功能所需的所有相关依赖（核心 Jar 包、第三方依赖等）打包整合，开发者只需引入一个 Starter 依赖，即可快速使用对应的功能，无需手动逐个引入依赖，避免了依赖版本冲突问题。

### 4.1 核心 Starter 分类

Spring Boot 提供了大量内置 Starter，按功能可分为核心 Starter 和第三方 Starter：

#### 4.1.1 官方核心 Starter（前缀：spring-boot-starter-*）

* `spring-boot-starter-web`：Web 开发必备，自动引入 Spring MVC、嵌入式 Tomcat、Jackson （JSON 解析）等依赖
* `spring-boot-starter-data-jpa`：数据访问，引入 Spring Data JPA 和 Hibernate 依赖
* `spring-boot-starter-jdbc`：JDBC 数据访问，引入 Spring JDBC 和 HikariCP（默认连接池）依赖
* `spring-boot-starter-redis`：Redis 集成，引入 Redis 客户端和 Spring 数据访问支持
* `spring-boot-starter-security`：安全认证，引入 Spring Security 依赖
* `spring-boot-starter-test`：测试支持，引入 JUnit、Mockito、Spring Test 等依赖

#### 4.1.2 第三方 Starter（前缀：*-spring-boot-starter）

第三方框架或工具为适配 Spring Boot 提供的 Starter，命名规范为“第三方名称-spring-boot-starter”：

* `mybatis-spring-boot-starter`：MyBatis 持久层框架 Starter
* `druid-spring-boot-starter`：Alibaba Druid 连接池 Starter
* `knife4j-spring-boot-starter`：接口文档工具 Knife4j（Swagger 增强版） Starter

### 4.2 Starter 的使用示例

以 Maven 项目为例，引入 `spring-boot-starter-web` 后，即可直接开发 Web 接口，无需额外配置：

```xml
<!-- pom.xml 中引入 Web Starter -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

```java
// 直接编写 Controller 接口，无需手动配置 Spring MVC
@RestController
@RequestMapping("/hello")
public class HelloController {
    @GetMapping
    public String hello() {
        return "Hello Spring Boot!";
    }
}
```

## 五、核心概念：嵌入式服务器（Embedded Server）

Spring Boot 内置了嵌入式的 Web 服务器，无需开发者单独下载、安装和配置服务器（如 Tomcat），可直接将 Spring Boot 应用打包为可执行 JAR 包，通过 `java -jar` 命令一键运行。

### 5.1 内置服务器类型

Spring Boot 默认使用 Tomcat 作为嵌入式服务器，同时支持替换为 Jetty、Undertow 等：

* Tomcat：默认，轻量级、稳定，适合大多数 Web 场景
* Jetty：异步性能好，适合长连接场景（如 WebSocket）
* Undertow：高性能、低内存占用，适合高并发场景

### 5.2 替换嵌入式服务器（以替换为 Undertow 为例）

通过 Maven 或 Gradle 排除默认的 Tomcat 依赖，引入目标服务器依赖即可：

```xml
<!-- pom.xml 中替换为 Undertow -->
<dependency>
    <groupId>org.springframework.boot</groupId>
   <artifactId>spring-boot-starter-web</artifactId>
    <!-- 排除默认的 Tomcat 依赖 -->
    <exclusions>
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-tomcat</artifactId>
        </exclusion>
    </exclusions>
</dependency>
<!-- 引入 Undertow 依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-undertow</artifactId>
</dependency>
```

### 5.3 配置嵌入式服务器参数

可在配置文件中修改服务器相关参数（如端口、访问路径、线程池等）：

```yaml
# application.yml 配置示例
server:
  port: 8081 # 服务器端口（默认 8080）
  servlet:
    context-path: /demo # 应用访问路径（默认 /）
  tomcat:
    max-threads: 200 # Tomcat 最大线程数
    min-spare-threads: 20 # 最小空闲线程数
```

## 六、核心概念：Spring Boot Actuator（应用监控）

Spring Boot Actuator 是 Spring Boot 提供的应用监控与管理组件，通过暴露一系列 HTTP 接口，可实时获取应用的运行状态（如健康状态、内存使用、线程情况、请求统计等），方便开发者进行运维和问题排查。

### 6.1 基本使用

1. 引入 Actuator Starter 依赖：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

1. 配置暴露监控接口（默认仅暴露 `/actuator/health`）：

```yaml
# application.yml 配置
management:
  endpoints:
    web:
      exposure:
        include: "*" # 暴露所有监控接口（生产环境不建议，需控制权限）
  endpoint:
    health:
      show-details: always # 显示健康检查的详细信息
```

1. 访问监控接口（默认端口与应用一致）：

   1. `http://localhost:8080/actuator/health`：查看应用健康状态（如数据库连接、Redis 连接是否正常）
   2. `http://localhost:8080/actuator/info`：查看应用自定义信息（需配置 `info.*` 参数）
   3. `http://localhost:8080/actuator/metrics`：查看应用指标（如内存使用、线程数、请求数）

## 七、核心配置文件

Spring Boot 提供了标准化的配置文件，用于覆盖默认配置或自定义应用参数，支持两种格式：`application.properties`（键值对格式）和 `application.yml`（YAML 格式，更简洁、易读）。

### 7.1 配置文件优先级

Spring Boot 会按以下优先级加载配置文件（高优先级覆盖低优先级）：

1. 命令行参数（如 `java -jar demo.jar --server.port=8082`）
2. 项目根目录下的 `config/` 文件夹中的配置文件
3. 项目根目录下的配置文件
4. 类路径下的 `config/` 文件夹中的配置文件
5. 类路径下的默认配置文件（`src/main/resources/application.yml`）

### 7.2 常用配置示例（YAML 格式）

```yaml
# 应用基础配置
spring:
  application:
    name: spring-boot-demo # 应用名称
  # 数据库配置（引入 spring-boot-starter-jdbc 或 data-jpa 时生效）
  datasource:
    url: jdbc:mysql://localhost:3306/test?useSSL=false&serverTimezone=UTC
    username: root
    password: 123456
    driver-class-name: com.mysql.cj.jdbc.Driver
  # Redis 配置（引入 spring-boot-starter-redis 时生效）
  redis:
    host: localhost
    port: 6379
    password:
    database: 0

# 服务器配置
server:
  port: 8081
  servlet:
    context-path: /demo

# 自定义配置（可通过 @Value 或 @ConfigurationProperties 注入）
custom:
  title: Spring Boot 演示
  version: 1.0.0
```

### 7.3 配置注入方式

开发者可通过以下方式将配置文件中的参数注入到 Java 类中：

7.3.1 @Value 注解（适合单个配置项）

```java
@RestController
public class ConfigController {
    // 注入自定义配置 custom.title
    @Value("${custom.title}")
    private String title;
  
    // 注入应用名称
    @Value("${spring.application.name}")
    private String appName;
  
    @GetMapping("/config")
    public String getConfig() {
        return "应用名称：" + appName + "，标题：" + title;
    }
}
```

#### 7.3.2 @ConfigurationProperties 注解（适合批量配置项）

```java
// 批量注入 custom 前缀的配置项
@ConfigurationProperties(prefix = "custom")
@Component
@Data // Lombok 注解，自动生成 getter/setter
public class CustomConfig {
    private String title;
    private String version;
}

// 使用配置类
@RestController
public class ConfigController {
    @Autowired
    private CustomConfig customConfig;
  
    @GetMapping("/customConfig")
    public CustomConfig getCustomConfig() {
        return customConfig; // 返回 {"title":"Spring Boot 演示","version":"1.0.0"}
    }
}
```

## 八、核心总结

Spring Boot 并非替代 Spring，而是对 Spring 框架的“简化封装”，其核心价值在于通过“约定优于配置”和“自动配置”消除繁琐配置，通过“Starter 起步依赖”简化依赖管理，通过“嵌入式服务器”简化部署流程，让开发者能够“快速开发、一键运行”企业级应用。

核心概念关联：

* Starter 依赖 → 自动引入功能所需组件 → 触发自动配置 → 无需手动配置 Bean
* 约定优于配置 → 标准化项目结构和配置 → 减少自定义配置成本
* 嵌入式服务器 + 可执行 JAR 包 → 简化部署流程，降低运维成本

关键记住：Spring Boot 的核心是“简化”，所有特性都是为了让开发者从繁琐的配置和依赖管理中解放出来，专注于业务逻辑开发。

## 八、Spring Boot 项目结构约定

Spring Boot 基于“约定大于配置”设计理念，定义了标准化的项目结构，无需手动配置组件扫描路径、资源加载位置等，核心约定如下（以 Maven 项目为例）：

```Plain
src/
├── main/
│   ├── java/                  # 核心Java代码目录（约定扫描此目录下的组件）
│   │   └── com/
│   │       └── example/
│   │           └── demo/      # 项目根包（建议全小写，反向域名格式）
│   │               ├── DemoApplication.java  # 主程序入口（必须在根包下）
│   │               ├── controller/           # 控制器层（接收请求）
│   │               ├── service/              # 服务层（业务逻辑）
│   │               │   └── impl/             # 服务实现类
│   │               ├── mapper/               # Mapper接口（数据访问层）
│   │               ├── entity/               # 实体类（与数据库表映射）
│   │               ├── config/               # 配置类（自定义Bean、框架配置）
│   │               ├── exception/            # 异常处理类
│   │               └── util/                 # 工具类
│   └── resources/             # 资源文件目录（约定资源加载路径）
│       ├── application.yml    # 核心配置文件（支持properties/yaml/yaml，推荐yaml）
│       ├── application-{profile}.yml  # 多环境配置文件（如dev/test/prod）
│       ├── static/            # 静态资源目录（存放JS、CSS、图片等）
│       ├── public/            # 公共静态资源目录（优先级低于static）
│       ├── resources/         # 其他资源目录（如配置文件模板、静态依赖）
│       └── templates/         # 模板文件目录（存放Thymeleaf/Freemarker等模板）
├── test/                      # 测试代码目录（与main/java结构对应）
│   └── java/
│       └── com/
│           └── example/
│               └── demo/
│                   ├── controller/
│                   ├── service/
│                   └── mapper/
└── pom.xml                    # Maven依赖配置文件（约定依赖管理方式）
```

#### （1）核心目录详细说明

* **src/main/java/根包**必须包含主程序入口类（如 DemoApplication.java），类上需添加 `@SpringBootApplication` 注解。Spring Boot 会自动扫描根包及所有子包下的 `@Controller`、`@Service`、`@Mapper`、`@Component` 等注解的组件，无需额外配置组件扫描。`// 主程序入口类示例（必须在根包下） ``package com.example.demo; `` ``import org.springframework.boot.SpringApplication; ``import org.springframework.boot.autoconfigure.SpringBootApplication; `` ``@SpringBootApplication // 包含@ComponentScan（自动扫描根包及子包） ``public class DemoApplication { ``    public static void main(String[] args) { ``        SpringApplication.run(DemoApplication.class, args); ``    } ``}`
* **src/main/resources**配置文件：核心配置文件默认命名为 `application.yml`（或 `application.properties`），存放数据库连接、服务器端口、框架参数等配置；多环境配置文件需遵循 `application-{profile}.yml` 命名规范（如 `application-dev.yml` 开发环境）。
* 静态资源：`static/` 目录用于存放JS、CSS、图片等静态资源，访问时可直接通过根路径访问（如 `http://localhost:8080/img/logo.png` 对应 `static/img/logo.png`）；`public/` 目录功能与 `static/` 一致，但优先级更低（当两者存在同名文件时，优先加载 `static/` 下的文件）。
* 模板文件：`templates/` 目录用于存放服务器端模板文件（如 Thymeleaf），Spring Boot 会自动识别模板引擎并渲染此目录下的文件，无需配置模板路径。

**src/test/java**约定存放单元测试、集成测试代码，目录结构需与 `src/main/java` 对应（如测试 `com.example.demo.service.UserService` 的测试类需放在 `com.example.demo.service.UserServiceTest`），类上需添加 `@SpringBootTest` 注解，用于加载 Spring 容器环境。`// 测试类示例 ``package com.example.demo.service; `` ``import org.junit.jupiter.api.Test; ``import org.springframework.beans.factory.annotation.Autowired; ``import org.springframework.boot.test.context.SpringBootTest; `` ``@SpringBootTest // 加载Spring容器，自动注入Bean ``public class UserServiceTest { ``    @Autowired ``    private UserService userService; `` ``    @Test ``    public void testGetUserById() { ``        // 测试逻辑 ``    } ``}`

**pom.xml**Maven 依赖管理文件，Spring Boot 约定通过 `spring-boot-starter-xxx` 引入场景依赖（如 `spring-boot-starter-web` 对应 Web 开发场景），无需手动指定依赖版本（父工程 `spring-boot-starter-parent` 已统一管理版本）。

#### （2）约定的核心优势

* 无需配置：无需手动配置组件扫描路径、资源加载路径、模板路径等，降低配置复杂度。
* 结构统一：团队开发遵循统一结构，减少沟通成本，便于项目维护。
* 自动识别：Spring Boot 自动识别主程序入口、配置文件、静态资源等，开箱即用。

#### （3）打破约定的场景（自定义配置）

若需打破默认约定（如自定义静态资源路径、组件扫描范围），可通过注解或配置实现：

```Plain
// 1. 自定义组件扫描范围（打破默认根包扫描）
@SpringBootApplication(scanBasePackages = "com.example") // 扫描com.example包下所有组件
public class DemoApplication { ... }

// 2. 自定义静态资源路径（application.yml中配置）
spring:
  resources:
    static-locations: classpath:/custom-static/ # 自定义静态资源目录为custom-static/
```

# Maven核心概念总结

Maven 是一款基于 Java 的项目构建工具，核心目标是自动化项目构建、统一项目结构、管理项目依赖。其所有功能均围绕以下核心概念展开，以下是关键概念的详细解析：

## 一、核心配置：POM（Project Object Model，项目对象模型）

POM 是 Maven 项目的核心配置文件，文件名固定为 `pom.xml`，存在于项目根目录。它定义了项目的基本信息、依赖关系、构建规则等，是 Maven 进行所有操作的依据。

### 核心作用：

* 描述项目基本信息（名称、版本、开发者、组织等）；
* 声明项目依赖（依赖的坐标、范围、排除等）；
* 配置构建过程（指定构建目标、插件、资源目录等）；
* 定义项目继承与聚合关系。

### 核心配置示例：

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
  
    <!-- 项目基本坐标（GAV） -->
    <groupId>com.demo</groupId>        <!-- 组织标识 -->
    <artifactId>maven-demo</artifactId> <!-- 项目标识 -->
    <version>1.0-SNAPSHOT</version>     <!-- 版本号 -->
  
    <!-- 依赖声明 -->
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
            <version>2.7.0</version>
        </dependency>
    </dependencies>
</project>
```

## 二、依赖定位：坐标（GAV）

Maven 采用“坐标系统”唯一标识一个项目或依赖包，通过三个核心属性（GAV）精准定位，确保依赖的唯一性和可追溯性。

### GAV 组成：

1. **groupId** ：组织/团体标识，通常以反向域名形式命名（如 `org.springframework.boot`），用于区分不同组织的项目；
2. **artifactId** ：项目/模块标识，是同一组织下不同项目的唯一名称（如 `spring-boot-starter-web`）；
3. **version** ：版本号，用于区分同一项目的不同版本，常见格式为 `主版本.次版本.修订号`，快照版本后缀为 `SNAPSHOT`（如 `2.7.0-SNAPSHOT`）。

核心意义：通过 GAV 坐标，Maven 能自动从仓库中下载指定依赖，无需手动管理 JAR 包。

## 三、依赖管理：依赖的传递性与范围

Maven 的核心优势之一是“依赖传递”，即项目依赖的 JAR 包所需的其他依赖，会被 Maven 自动下载并引入，无需手动声明。同时，通过“依赖范围”控制依赖在不同构建阶段的可用性。

### 1. 依赖传递性

示例：项目依赖 `spring-boot-starter-web`，Maven 会自动传递引入 `spring-core`、`spring-context`等依赖。

解决冲突：当传递依赖出现版本冲突时，Maven 遵循“最短路径优先”和“声明优先”原则；也可通过 `<exclusions>` 排除不需要的传递依赖。

### 2. 依赖范围（scope）

通过 `<scope>` 标签指定依赖的作用范围，核心范围如下：

| 范围                                                                                                  | 作用描述                                         | 适用场景                               |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------- |
| ----------------------------------------------------------------------------------------------------- |                                                  |                                        |
| compile（默认）                                                                                       | 编译、测试、运行阶段均有效，会打包进入最终产物   | 项目核心依赖（如 Spring 核心包）       |
| -                                                                                                     | -                                                | -                                      |
| test                                                                                                  | 仅测试阶段有效，不打包进入最终产物               | 测试框架（如 JUnit、TestNG）           |
| provided                                                                                              | 编译、测试阶段有效，运行阶段由容器提供（不打包） | Servlet API、JSP API（由 Tomcat 提供） |
| runtime                                                                                               | 测试、运行阶段有效，编译阶段不需要               | 数据库驱动（如 MySQL 驱动）            |
| system                                                                                                | 依赖本地系统中的 JAR 包，需指定路径（不推荐）    | 本地自定义非仓库依赖                   |

## 四、资源存储：仓库（Repository）

Maven 仓库是用于存储项目依赖（JAR 包、POM 文件）和项目构建产物的场所，分为三类：

1. **本地仓库** ：位于开发者本地磁盘（默认路径：`~/.m2/repository`），是依赖的缓存目录。Maven 优先从本地仓库获取依赖，本地没有时才从远程仓库下载。
2. **中央仓库** ：Maven 官方提供的远程仓库（https://repo.maven.apache.org/maven2/），包含全球大部分开源项目的依赖，无需配置即可使用。
3. **私服（远程仓库）** ：企业/组织内部搭建的私有仓库，用于存储内部项目依赖、第三方付费依赖等，需在 pom.xml 或 settings.xml 中配置地址。

## 五、构建流程：生命周期与插件

Maven 定义了标准化的项目构建生命周期，每个生命周期包含一系列有序的“阶段（Phase）”，执行某个阶段时，会自动执行其之前的所有阶段。同时，Maven 的核心功能由“插件”实现，阶段与插件绑定完成具体构建操作。

### 1. 核心生命周期

Maven 有三套相互独立的生命周期，最常用的是“默认生命周期（Default Lifecycle）”，涵盖项目构建的完整流程：

* validate：验证项目配置是否正确；
* compile：编译项目源代码（将 Java 文件编译为 class 文件）；
* test：运行测试用例（依赖 test 范围的依赖）；
* package：将编译后的代码打包（如 JAR、WAR 包）；
* install：将打包产物安装到本地仓库，供其他项目依赖；
* deploy：将打包产物部署到私服，供团队共享。

示例：执行 `mvn package` 命令时，会自动执行 validate → compile → test → package 阶段。

### 2. 插件（Plugin）

Maven 本身不实现具体构建功能，而是通过插件完成（如编译由 `maven-compiler-plugin` 实现，打包由 `maven-jar-plugin` 实现）。

核心特性：

* 插件与生命周期阶段绑定（如 compile 阶段绑定 `maven-compiler-plugin:compile`）；
* 可在 pom.xml 中配置插件参数（如指定 Java 编译版本）；
* 常用插件：`maven-compiler-plugin`（编译）、`maven-surefire-plugin`（测试）、`maven-jar-plugin`（打包 JAR）。

## 六、多模块管理：继承与聚合

对于复杂项目（如微服务项目），Maven 支持“多模块”管理，通过“继承”和“聚合”实现模块间的复用和统一构建。

### 1. 继承（Inheritance）

目的：抽取多个子模块的公共配置（如公共依赖、插件配置）到父模块，子模块继承父模块配置，减少重复。

实现方式：

* 父模块 pom.xml 中声明 `<packaging>pom</packaging>`（标识为父项目）；
* 子模块通过 `<parent>` 标签指定父模块的 GAV 坐标。

### 2. 聚合（Aggregation）

目的：通过一个“聚合模块”统一管理所有子模块，执行聚合模块的构建命令时，会自动构建所有子模块。

实现方式：

* 聚合模块 pom.xml 中声明 `<packaging>pom</packaging>`；
* 通过 `<modules>` 标签列出所有子模块名称（如 `<module>user-service</module>`）。

核心区别：继承是“子模块复用父模块配置”，聚合是“统一构建所有子模块”，通常一个父模块同时承担聚合功能。

## 七、核心命令

Maven 通过命令行执行构建操作，常用核心命令：

* `mvn clean`：清理项目构建产物（删除 target 目录）；
* `mvn compile`：编译项目源代码；
* `mvn test`：运行测试用例，生成测试报告；
* `mvn package`：打包项目（生成 JAR/WAR 包，位于 target 目录）；
* `mvn install`：将打包产物安装到本地仓库；
* `mvn deploy`：将打包产物部署到私服；
* `mvn dependency:tree`：查看项目依赖树（分析依赖冲突）。

# 数据库核心概念总结

数据库（Database，DB）是按照数据结构组织、存储和管理数据的仓库，其核心价值在于实现数据的持久化存储、高效访问与共享管理。以下是数据库领域的核心概念解析，涵盖基础定义、核心组件、数据模型等关键维度：

## 一、基础核心概念

### 1. 数据库（DB）

长期存储在计算机内、有组织、可共享的数据集合。数据以一定的结构（如表格、键值对）存储，具备冗余度低、独立性高、易扩展等特点，避免了传统文件存储的混乱与低效。

示例：企业的用户信息库、电商平台的订单数据库、学校的学生成绩库。

### 2. 数据库管理系统（DBMS）

用于管理数据库的软件系统，是用户与数据库之间的接口。负责数据的定义、组织、存储、检索、更新、维护等操作，同时提供数据安全、并发控制、故障恢复等核心功能。

常见DBMS产品：

* 关系型：MySQL、Oracle、SQL Server、PostgreSQL；
* 非关系型：MongoDB（文档型）、Redis（键值型）、Elasticsearch（搜索型）、HBase（列存储型）。

### 3. 数据库系统（DBS）

由数据库（DB）、数据库管理系统（DBMS）、数据库管理员（DBA）、应用程序及用户组成的完整系统。其中DBA负责数据库的规划、部署、维护、优化等核心工作，保障系统稳定运行。

## 二、核心数据模型

数据模型是对数据特征的抽象描述，定义了数据的组织结构、关系及操作规则，是数据库设计的基础。主流数据模型分为以下四类：

### 1. 层次模型（Hierarchical Model）

以“树状结构”组织数据，数据之间是一对多的层级关系（如父子关系）。顶层为根节点，每个子节点仅有一个父节点。

特点：结构简单、查询效率高；但不适合表示多对多关系，扩展性差。

适用场景：早期的IMS数据库、组织架构管理等层级明确的场景。

### 2. 网状模型（Network Model）

以“图状结构”组织数据，允许一个节点有多个父节点，可直接表示多对多关系。

特点：比层次模型灵活，能处理复杂关系；但结构复杂，维护难度大。

适用场景：早期的CODASYL数据库、复杂的工程数据管理等。

### 3. 关系模型（Relational Model）

以“二维表格”（关系）为核心组织数据，表格中的每行是一条记录（元组），每列是一个属性（字段）。数据之间的关系通过“主键-外键”关联实现。

核心特点：

* 数据结构简单直观，易于理解和使用；
* 通过SQL语言实现统一的数据操作，通用性强；
* 数据独立性高，冗余度可控。

适用场景：绝大多数业务系统（电商、金融、政务等），是目前应用最广泛的数据模型。

### 4. NoSQL模型（非关系模型）

针对关系模型的局限性（如海量数据存储、高并发访问、灵活 schema 需求）产生的新型数据模型，不依赖于固定的表格结构。

主流类型及特点：

| NoSQL类型                                                                              | 核心特点                              | 代表产品         | 适用场景                     |
| -------------------------------------------------------------------------------------- | ------------------------------------- | ---------------- | ---------------------------- |
| -------------------------------------------------------------------------------------- |                                       |                  |                              |
| 文档型                                                                                 | 以JSON/BSON文档存储数据，schema灵活   | MongoDB          | 内容管理、用户画像、日志存储 |
| -                                                                                      | -                                     | -                | -                            |
| 键值型                                                                                 | 以“键-值”对存储，查询速度极快         | Redis、Memcached | 缓存、会话存储、计数器       |
| 列存储型                                                                               | 按列存储数据，适合海量数据批量查询    | HBase、Cassandra | 大数据分析、时序数据存储     |
| 图数据库                                                                               | 以“节点-边”表示关系，擅长处理复杂关联 | Neo4j、ArangoDB  | 社交网络、推荐系统、路径分析 |

## 三、关系型数据库核心组件

基于关系模型的数据库，核心组件围绕“表格”展开，主要包括：

### 1. 表（Table）

存储数据的二维结构，是关系型数据库的基本单位。每个表对应现实世界中的一个实体（如“用户表”“订单表”）。

核心属性：

* 字段（Column）：表中的一列，定义数据的类型（如INT、VARCHAR、DATE）和约束（如非空、唯一）；
* 记录（Row/Tuple）：表中的一行，是一条完整的实体数据（如一条用户记录包含ID、姓名、手机号等字段值）；
* 表结构（Schema）：表的定义信息，包括字段名、数据类型、约束、索引等。

### 2. 主键（Primary Key，PK）

用于唯一标识表中每条记录的字段（或字段组合），具备以下特性：

* 唯一性：表中无重复的主键值；
* 非空性：主键字段不能为NULL；
* 稳定性：主键值尽量不修改（如用户ID）。

示例：用户表的“user_id”字段作为主键，唯一标识每个用户。

### 3. 外键（Foreign Key，FK）

用于关联两个表的字段，是一个表中引用另一个表主键的字段。通过外键实现表之间的关系（如一对一、一对多、多对多）。

示例：订单表的“user_id”字段作为外键，关联用户表的主键“user_id”，表示“一个用户可拥有多个订单”的一对多关系。

### 4. 索引（Index）

为提升查询效率而创建的“数据结构”（如B+树、哈希表），相当于数据库的“目录”。通过索引可快速定位数据，避免全表扫描。

核心特点：

* 提升查询速度，但会降低插入、更新、删除的效率（需同步维护索引）；
* 占用额外存储空间；
* 适合创建在查询频繁、区分度高的字段上（如用户ID、手机号）。

常见索引类型：主键索引、唯一索引、普通索引、联合索引、全文索引。

### 5. 约束（Constraint）

用于保证数据的完整性和一致性的规则，常见约束包括：

* 非空约束（NOT NULL）：字段值不能为NULL；
* 唯一约束（UNIQUE）：字段值在表中唯一（可允许NULL）；
* 主键约束（PRIMARY KEY）：非空+唯一，即主键的核心约束；
* 外键约束（FOREIGN KEY）：保证关联表之间的数据一致性；
* 检查约束（CHECK）：限制字段值的范围（如年龄范围1-120）。

## 四、数据库核心特性

数据库的核心价值通过以下特性实现，保障数据的安全、可靠与高效使用：

### 1. 数据独立性

数据与应用程序相互独立，分为两种类型：

* 物理独立性：数据的存储结构（如存储路径、存储格式）变化时，不影响应用程序；
* 逻辑独立性：数据的逻辑结构（如字段增减、表关系调整）变化时，应用程序无需修改。

### 2. 事务（Transaction）

数据库中一系列不可分割的操作集合，要么全部执行成功，要么全部执行失败（回滚），保障数据的一致性。事务具备ACID特性：

* 原子性（Atomicity）：事务是不可分割的最小单位，操作要么全成，要么全败；
* 一致性（Consistency）：事务执行前后，数据的完整性约束不被破坏（如转账前后总金额不变）；
* 隔离性（Isolation）：多个事务并发执行时，相互隔离，不影响彼此的执行结果；
* 持久性（Durability）：事务执行成功后，数据的修改永久保存，即使系统故障也不丢失。

### 3. 并发控制

多个用户/应用程序同时访问数据库时，通过锁机制、隔离级别等手段，避免并发操作导致的数据不一致（如脏读、不可重复读、幻读）。

常见并发问题：

* 脏读：读取到未提交的事务数据；
* 不可重复读：同一事务内，多次读取同一数据，结果不一致；
* 幻读：同一事务内，多次查询同一条件，返回的记录数不一致。

### 4. 故障恢复

当数据库发生故障（如系统崩溃、断电、磁盘损坏）时，通过日志（如重做日志、回滚日志）、备份等机制，恢复数据到故障前的一致状态，保障数据可靠性。

## 五、核心数据操作（CRUD）

数据库的基本操作围绕数据的“增删改查”展开，是应用程序与数据库交互的核心：

* 创建（Create）：向数据库中插入新数据（如INSERT语句）；
* 读取（Read）：查询数据库中的数据（如SELECT语句）；
* 更新（Update）：修改数据库中已有的数据（如UPDATE语句）；
* 删除（Delete）：删除数据库中的数据（如DELETE语句）。

在关系型数据库中，这些操作通过SQL语言实现；在NoSQL数据库中，多通过API实现（如MongoDB的insertOne、find方法）。

## 六、数据库设计核心原则

数据库设计的核心目标是“结构合理、冗余度低、查询高效、易于维护”，关键原则包括：

### 1. 三大范式（Normal Form）

用于规范表结构设计，减少数据冗余和异常：

* 第一范式（1NF）：字段原子性，不可再分割（如“姓名”字段不能同时存储“姓名+性别”）；
* 第二范式（2NF）：在1NF基础上，消除部分依赖，即非主键字段必须完全依赖于主键；
* 第三范式（3NF）：在2NF基础上，消除传递依赖，即非主键字段不依赖于其他非主键字段。

### 2. 适度冗余

严格遵循范式可能导致多表关联查询效率低，实际设计中可适当保留冗余字段（如订单表存储“用户名”，避免每次查询关联用户表），平衡冗余与查询效率。

### 3. 合理命名

表名、字段名采用清晰的语义化命名（如“user_info”“order_id”），避免模糊或冗余的命名，提升可维护性。

# MySQL核心语法总结（附示例）

MySQL 遵循 SQL 标准，同时具备自身专属语法特性。以下总结其高频核心语法，按“数据操纵、表结构操作、事务控制、特有功能”分类，每个语法点配套可直接运行的示例，适配日常开发场景。

## 一、数据操纵语言（DML）：增删改查

用于对表中数据进行核心操作，是日常开发最常用的语法集合。

### 1. 插入数据（INSERT）

支持单条插入、批量插入，可指定字段或省略字段（按表结构顺序）。

```sql
-- 1. 指定字段批量插入（推荐）
INSERT INTO user_info(username, age, create_time)
VALUES 
('张三', 22, '2024-01-01 10:30:00'),
('李四', 25, CURRENT_TIMESTAMP); -- 用 CURRENT_TIMESTAMP 取当前时间

-- 2. 省略字段插入（需按表中所有字段顺序）
INSERT INTO user_info
VALUES (null, '王五', 28, '2024-01-02 09:15:00', 1); -- id 自增可传 null
```

### 2. 查询数据（SELECT）

支持基础查询、条件过滤、排序、去重、聚合等，含 MySQL 专属分页语法。

```sql
-- 1. 基础查询（去重+排序）
SELECT DISTINCT username, age FROM user_info 
WHERE age > 20 
ORDER BY age DESC; -- 按年龄降序

-- 2. 模糊查询（LIKE）
SELECT * FROM user_info 
WHERE username LIKE '%张%'; -- 匹配含"张"字的用户名

-- 3. 聚合查询（GROUP BY + HAVING）
SELECT dept_id, COUNT(*) 员工数量, AVG(age) 平均年龄 
FROM user_info 
GROUP BY dept_id 
HAVING COUNT(*) > 3; -- 过滤出员工数大于3的部门

-- 4. 分页查询（MySQL 专属 LIMIT）
SELECT * FROM user_info 
ORDER BY id ASC 
LIMIT 10, 10; -- 查询第11-20条数据（偏移量10，条数10，偏移量从0开始）

-- 5. 子查询（关联查询替代方案）
SELECT * FROM user_info 
WHERE dept_id IN (SELECT id FROM dept WHERE dept_name = '技术部'); -- 查技术部员工
```

### 3. 更新数据（UPDATE）

支持单条/批量更新，可结合条件精准更新，务必加 WHERE 子句避免全表更新。

```sql
-- 1. 基础更新
UPDATE user_info 
SET age = 23, username = '张三三' 
WHERE id = 1; -- 精准更新id=1的用户

-- 2. 批量更新（按条件）
UPDATE user_info 
SET dept_id = 2 
WHERE create_time < '2024-01-01'; -- 更新2024年之前创建的用户部门

-- 3. 结合函数更新
UPDATE user_info 
SET create_time = DATE_ADD(create_time, INTERVAL 1 DAY) 
WHERE id = 3; -- 给id=3的用户创建时间加1天
```

### 4. 删除数据（DELETE）

支持条件删除，也可通过 TRUNCATE 清空全表（不可回滚，速度更快）。

```sql
-- 1. 条件删除
DELETE FROM user_info 
WHERE id = 5; -- 精准删除id=5的用户

-- 2. 批量删除（按范围）
DELETE FROM user_info 
WHERE age < 18; -- 删除未成年用户

-- 3. 清空全表（不可回滚，谨慎使用）
TRUNCATE TABLE user_info; -- 清空表数据，保留表结构，自增id重置为1
```

## 二、数据定义语言（DDL）：表结构操作

用于创建、修改、删除表及索引等数据库对象，含 MySQL 特有数据类型（枚举、集合）语法。

### 1. 创建表（CREATE TABLE）

支持自增主键、默认值、非空约束等，可定义 MySQL 特有数据类型。

```sql
-- 1. 基础表创建（含自增主键）
CREATE TABLE user_info (
  id INT PRIMARY KEY AUTO_INCREMENT, -- 自增主键（MySQL 专属 AUTO_INCREMENT）
  username VARCHAR(50) NOT NULL UNIQUE, -- 非空+唯一约束
  age INT DEFAULT 0, -- 默认值0
  gender ENUM('男','女','未知') DEFAULT '未知', -- MySQL 特有枚举类型
  hobby SET('篮球','足球','读书','跑步') DEFAULT NULL, -- MySQL 特有集合类型
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP, -- 默认当前时间
  dept_id INT,
  -- 外键约束（关联部门表）
  FOREIGN KEY (dept_id) REFERENCES dept(id) ON DELETE SET NULL
);

-- 2. 复制表结构（仅复制结构，不复制数据）
CREATE TABLE user_info_copy LIKE user_info;
```

### 2. 修改表结构（ALTER TABLE）

支持添加/删除字段、修改字段类型、重命名字段/表等操作。

```sql
-- 1. 添加字段
ALTER TABLE user_info 
ADD COLUMN email VARCHAR(100) UNIQUE AFTER username; -- 在username后添加email字段

-- 2. 修改字段类型及约束
ALTER TABLE user_info 
MODIFY COLUMN age TINYINT UNSIGNED DEFAULT 0; -- 改为无符号tinyint，默认0

-- 3. 重命名字段
ALTER TABLE user_info 
CHANGE COLUMN email user_email VARCHAR(100) UNIQUE; -- 把email改为user_email

-- 4. 删除字段
ALTER TABLE user_info 
DROP COLUMN hobby; -- 删除hobby字段

-- 5. 重命名表
ALTER TABLE user_info 
RENAME TO sys_user;
```

### 3. 删除表（DROP TABLE）

支持直接删除表，或加 IF EXISTS 避免表不存在时报错。

```sql
-- 1. 直接删除表（表不存在则报错）
DROP TABLE sys_user;

-- 2. 安全删除（表存在则删除，推荐）
DROP TABLE IF EXISTS sys_user;
```

### 4. 创建索引（CREATE INDEX）

支持普通索引、唯一索引、联合索引，提升查询效率。

```sql
-- 1. 普通索引（查询频繁字段）
CREATE INDEX idx_sys_user_username ON sys_user(username);

-- 2. 唯一索引（字段值唯一，如邮箱）
CREATE UNIQUE INDEX idx_sys_user_email ON sys_user(user_email);

-- 3. 联合索引（多字段查询场景）
CREATE INDEX idx_sys_user_dept_create ON sys_user(dept_id, create_time);
```

## 三、事务控制语言（TCL）

MySQL 支持标准事务 ACID 特性，通过相关命令控制事务提交与回滚。

```sql
-- 1. 开启事务（关闭自动提交）
START TRANSACTION; -- 或简写 BEGIN

-- 2. 核心操作（增删改，可多条）
UPDATE sys_user SET dept_id = 3 WHERE id = 1;
INSERT INTO sys_user(username, age) VALUES('赵六', 30);

-- 3. 设置保存点（可选，用于局部回滚）
SAVEPOINT sp1;

-- 4. 局部回滚（若某步操作出错）
ROLLBACK TO sp1;

-- 5. 提交事务（所有操作成功后执行，数据永久生效）
COMMIT;

-- 6. 全量回滚（任何一步出错时，撤销所有操作）
ROLLBACK;
```

## 四、MySQL 特有语法与函数

整理 MySQL 专属的高频函数及语法，提升开发效率。

### 1. 常用专属函数

```sql
-- 1. 日期函数
SELECT NOW(); -- 获取当前日期+时间（如：2024-05-20 14:30:00）
SELECT DATE_FORMAT(create_time, '%Y-%m-%d') FROM sys_user; -- 日期格式化
SELECT DATE_ADD(NOW(), INTERVAL 7 DAY); -- 计算7天后的日期

-- 2. 字符串函数
SELECT CONCAT(username, '-', dept_id) FROM sys_user; -- 字符串拼接
SELECT LENGTH(username) FROM sys_user; -- 获取字符串字节长度
SELECT SUBSTRING(username, 1, 2) FROM sys_user; -- 截取字符串前2位

-- 3. 空值处理函数
SELECT IFNULL(age, 0) FROM sys_user; -- 空值替换（age为null则返回0）
SELECT IF(age > 30, '中年', '青年') FROM sys_user; -- 条件判断函数

-- 4. 数字函数
SELECT ROUND(AVG(age), 1) FROM sys_user; -- 平均值保留1位小数
SELECT RAND(); -- 生成0-1随机数
```

### 2. 特有查询语法

```sql
-- 1. 限制查询条数（TOP N）
SELECT * FROM sys_user ORDER BY id LIMIT 5; -- 查询前5条数据

-- 2. 批量插入并忽略重复（基于唯一约束）
INSERT IGNORE INTO sys_user(username, age) 
VALUES ('张三', 22); -- 若username已存在（唯一约束），则忽略此条插入

-- 3. 插入或更新（存在则更新，不存在则插入）
REPLACE INTO sys_user(id, username, age) 
VALUES (1, '张三', 23); -- 若id=1存在则更新，不存在则插入

-- 4. 按字段分组统计并排序（统计各部门人数并排序）
SELECT dept_id, COUNT(*) 人数 
FROM sys_user 
GROUP BY dept_id 
ORDER BY 人数 DESC;
```

# MyBatis 与 MyBatis Plus 核心概念与使用方式总结

MyBatis 是一款基于 Java 的持久层框架，核心是通过 XML/注解映射 SQL 语句，实现 Java 对象与数据库表的关联；MyBatis Plus（简称 MP）是在 MyBatis 基础上的增强工具，保留 MyBatis 核心功能，简化 CRUD 操作，提供通用 Mapper、条件构造器等高效特性。以下从核心概念、使用方式、示例演示三部分展开说明。

## 一、核心概念

### 1. MyBatis 核心概念

* **ORM 映射** ：Object Relational Mapping（对象关系映射），将 Java 实体类与数据库表建立关联，实现数据在对象与关系型数据库间的转换。
* **SqlSessionFactory** ：MyBatis 核心工厂类，通过读取核心配置文件（mybatis-config.xml）构建，用于创建 SqlSession。
* **SqlSession** ：数据库会话对象，封装了 JDBC 连接，用于执行 SQL 语句、提交/回滚事务，是 MyBatis 与数据库交互的核心对象。
* **Mapper 接口/映射文件** ：Mapper 接口定义数据操作方法，映射文件（*.xml）或注解用于编写 SQL 语句，实现接口方法与 SQL 的绑定。
* **参数映射（ParameterMap）** ：定义方法参数与 SQL 语句中参数的对应关系，支持基本类型、实体类、Map 等参数类型。
* **结果映射（ResultMap）** ：定义 SQL 查询结果与 Java 实体类属性的对应关系，解决字段名与属性名不一致问题。

### 2. MyBatis Plus 核心概念

MyBatis Plus 基于 MyBatis，核心是“增强不改变”，在保留原功能的基础上，简化开发流程，核心概念包括：

* **通用 Mapper（BaseMapper）** ：内置封装了单表 CRUD 操作（增删改查）的 Mapper 接口，开发者无需编写基础 SQL，直接继承即可使用。
* **条件构造器（Wrapper）** ：提供 LambdaQueryWrapper、QueryWrapper 等类，通过链式编程构建复杂 SQL 条件（where、order by 等），无需手动拼接 SQL。
* **实体类注解** ：通过 @TableName、@TableId、@TableField 等注解，快速建立实体类与数据库表的映射，替代 MyBatis 繁琐的 ResultMap 配置。
* **代码生成器** ：通过配置自动生成实体类、Mapper 接口、映射文件、Service、Controller 等代码，大幅减少重复开发工作。
* **分页插件** ：内置分页功能，无需编写分页 SQL，通过配置插件即可实现物理分页（而非内存分页），支持多种数据库。

## 四、关键注意事项

* MyBatis Plus 完全兼容 MyBatis，现有 MyBatis 项目可无缝迁移到 MyBatis Plus，无需修改原有代码。
* 使用 MyBatis Plus 条件构造器时，避免硬编码字段名（优先使用 LambdaQueryWrapper），减少字段名修改导致的 bug。
* MyBatis Plus 分页插件需手动配置，且需指定数据库类型，否则可能出现分页异常。
* 复杂 SQL 场景（如多表联查），MyBatis Plus 可通过自定义 Mapper 方法+注解/SQL 语句实现，兼顾简化开发与灵活性。

# Redis核心概念

Redis（Remote Dictionary Server）是一款开源的高性能键值对（Key-Value）内存数据库，支持多种数据结构，兼具持久化、高可用、分布式等特性，广泛用于缓存、会话存储、消息队列等场景。以下从核心概念和使用例子两部分展开，涵盖命令行操作与Spring Boot整合实践。

## 一、核心概念

### 1. 核心定位：内存数据库

Redis数据默认存储在内存中，读写速度极快（读速约110000次/秒，写速约81000次/秒），但内存数据易丢失，因此提供持久化机制保障数据安全。

### 2. 核心数据结构

Redis支持多种原生数据结构，覆盖大部分开发场景，是其核心优势之一：

* **String（字符串）** ：最基础数据结构，可存储字符串、数字、二进制数据，最大512MB。
* **Hash（哈希）** ：键值对集合（类似Java的HashMap），适合存储对象（如用户信息）。
* **List（列表）** ：有序字符串列表（双向链表实现），支持两端插入/删除，适合实现队列、栈。
* **Set（集合）** ：无序字符串集合，不允许重复元素，支持交集、并集、差集等运算。
* **Sorted Set（有序集合）** ：Set的有序版本，每个元素关联一个分数（score），按分数排序，适合排行榜、优先级队列。
* **其他扩展结构** ：BitMap（位图，用于布尔值存储）、HyperLogLog（基数统计）、Geo（地理位置）。

### 3. 持久化机制

将内存数据持久化到磁盘，避免重启后数据丢失，核心两种方式：

* **RDB（Redis Database）** ：在指定时间间隔内，将内存数据快照写入磁盘（二进制文件），适合备份、大规模数据恢复。
* **AOF（Append Only File）** ：记录所有写操作命令到日志文件，重启时重新执行命令恢复数据，数据一致性更高（可配置同步策略）。

### 4. 高可用与分布式

* **主从复制** ：一个主节点（Master）同步数据到多个从节点（Slave），实现读写分离（主写从读），提升读性能。
* **哨兵模式（Sentinel）** ：监控主从节点，主节点故障时自动选举新主节点，保障高可用。
* **Redis Cluster（集群）** ：将数据分片存储在多个节点，解决单节点内存限制，支持水平扩展。

### 5. 缓存相关概念

* **过期策略** ：支持为Key设置过期时间，过期后自动删除（三种策略：定时删除、惰性删除、定期删除）。
* **内存淘汰策略** ：内存满时，按规则删除数据（如LRU：最近最少使用、LFU：最不经常使用）。

### 2. 核心数据结构命令行例子

#### （1）String 字符串

适用场景：存储用户Token、验证码、计数器等。

```bash
# 1. 设置值（key=user:token:1001，value=xxx，过期时间3600秒）

# 2. 获取值

# 3. 自增（计数器，如文章阅读量）

# 4. 自减

# 5. 追加字符串
APPEND user:name:1001 " Zhang"  # 原value=“Li”，追加后为“Li Zhang”
```

#### （2）Hash 哈希

适用场景：存储用户信息、商品详情等对象数据。

```bash
# 1. 设置哈希字段（key=user:info:1001，字段=username/age/email）
HMSET user:info:1001 username "张三" age 22 email "zhangsan@example.com"

# 2. 获取单个字段值
HGET user:info:1001 username

# 3. 获取所有字段和值
HGETALL user:info:1001

# 4. 获取所有字段
HKEYS user:info:1001

# 5. 获取所有值
HVALS user:info:1001

# 6. 自增字段值（如用户积分）
HINCRBY user:info:1001 score 10

# 7. 删除字段
HDEL user:info:1001 email
```

#### （3）List 列表

适用场景：消息队列、最新消息列表、栈（LIFO）/队列（FIFO）。

```bash
# 1. 从列表左侧插入元素（栈/队列入队）
LPUSH msg:queue "msg1" "msg2"  # 左侧插入，列表为[msg2, msg1]

# 2. 从列表右侧插入元素
RPUSH msg:queue "msg3"  # 右侧插入，列表为[msg2, msg1, msg3]

# 3. 从左侧弹出元素（栈出栈/队列出队）
LPOP msg:queue  # 弹出msg2，列表变为[msg1, msg3]

# 4. 从右侧弹出元素
RPOP msg:queue  # 弹出msg3，列表变为[msg1]

# 5. 获取列表长度
LLEN msg:queue

# 6. 获取列表指定范围元素（0=-1表示所有）
LRANGE msg:queue 0 -1
```

#### （4）Set 集合

适用场景：用户标签、好友去重、交集/并集运算（如共同好友）。

```bash
# 1. 向集合添加元素
SADD user:tags:1001 "Java" "Redis" "SpringBoot"

# 2. 获取集合所有元素
SMEMBERS user:tags:1001

# 3. 判断元素是否在集合中
SISMEMBER user:tags:1001 "Java"  # 返回1（存在）/0（不存在）

# 4. 获取集合大小
SCARD user:tags:1001

# 5. 集合交集（共同标签：用户1001和1002）
SADD user:tags:1002 "Java" "MySQL" "SpringBoot"
SINTER user:tags:1001 user:tags:1002  # 结果：Java, SpringBoot

# 6. 集合并集
SUNION user:tags:1001 user:tags:1002  # 结果：Java, Redis, SpringBoot, MySQL

# 7. 删除集合元素
SREM user:tags:1001 "Redis"
```

#### （5）Sorted Set 有序集合

适用场景：排行榜（如商品销量、用户积分）、优先级队列。

```bash
# 1. 向有序集合添加元素（score=分数，member=元素）
ZADD goods:sales:rank 100 "商品A" 200 "商品B" 150 "商品C"

# 2. 按分数升序获取元素（0=-1表示所有）
ZRANGE goods:sales:rank 0 -1 WITHCOUNTS  # WITHCOUNTS显示分数

# 3. 按分数降序获取元素（排行榜常用）
ZREVRANGE goods:sales:rank 0 2 WITHCOUNTS  # 获取前3名

# 4. 获取元素分数
ZSCORE goods:sales:rank "商品B"  # 返回200

# 5. 元素分数自增（销量+10）
ZINCRBY goods:sales:rank 10 "商品A"  # 商品A分数变为110

# 6. 获取元素排名（降序，第1名返回0）
ZREVRANK goods:sales:rank "商品B"  # 返回0
```

#### 步骤3：配置 RedisTemplate（自定义序列化）

默认 RedisTemplate 使用 JDK 序列化，可读性差，自定义为 JSON 序列化（使用 Jackson）：

```java
import com.fasterxml.jackson.annotation.JsonAutoDetect;
import com.fasterxml.jackson.annotation.PropertyAccessor;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.connection.lettuce.LettuceConnectionFactory;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.data.redis.serializer.Jackson2JsonRedisSerializer;
import org.springframework.data.redis.serializer.StringRedisSerializer;

@Configuration
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(LettuceConnectionFactory lettuceConnectionFactory) {
        RedisTemplate<String, Object> redisTemplate = new RedisTemplate<>();
        redisTemplate.setConnectionFactory(lettuceConnectionFactory);

        // 配置JSON序列化器（Key用String序列化，Value用JSON序列化）
        Jackson2JsonRedisSerializer<Object> jackson2JsonRedisSerializer = new Jackson2JsonRedisSerializer<>(Object.class);
        ObjectMapper objectMapper = new ObjectMapper();
        // 开启实体类字段的访问权限（包括private）
        objectMapper.setVisibility(PropertyAccessor.ALL, JsonAutoDetect.Visibility.ANY);
        // 支持Java 8时间类型（LocalDateTime等）
        objectMapper.findAndRegisterModules();
        jackson2JsonRedisSerializer.setObjectMapper(objectMapper);

        // Key序列化
        redisTemplate.setKeySerializer(new StringRedisSerializer());
        // Value序列化
        redisTemplate.setValueSerializer(jackson2JsonRedisSerializer);
        // Hash Key序列化
        redisTemplate.setHashKeySerializer(new StringRedisSerializer());
        // Hash Value序列化
        redisTemplate.setHashValueSerializer(jackson2JsonRedisSerializer);

        redisTemplate.afterPropertiesSet();
        return redisTemplate;
    }
}
```

    // -------------------------- 通用操作 --------------------------
    public Boolean hasKey(String key) {

    }

## 三、关键注意事项

* **序列化问题** ：必须自定义 RedisTemplate 序列化方式（如JSON），避免默认JDK序列化导致的乱码和兼容性问题。
* **过期时间设置** ：缓存场景务必为Key设置过期时间，避免内存溢出。
* **缓存一致性** ：更新数据库后，需及时更新或删除Redis缓存，避免缓存与数据库数据不一致（可采用“更新数据库+删除缓存”策略）。
* **高并发问题** ：避免缓存穿透（缓存和数据库都无数据，可缓存空值）、缓存击穿（热点Key过期，可加互斥锁）、缓存雪崩（大量Key同时过期，可设置随机过期时间）。
* **持久化选择** ：追求性能选RDB，追求数据一致性选AOF；生产环境建议开启混合持久化（RDB+AOF）。

# Kafka核心概念

Kafka是分布式发布-订阅消息队列系统，核心定位是“高吞吐、高可用、持久化的消息中间件”，主要用于日志收集、业务消息解耦、实时流处理等场景，核心概念如下：

## 1. Topic（主题）

Topic是消息的“分类容器”，生产者会把消息发送到指定的Topic中，消费者则从指定的Topic订阅消息。核心作用是实现消息按业务维度分类，比如订单相关的消息统一发送到“order_topic”，日志相关的消息发送到“log_topic”，便于业务隔离和管理。

## 2. Partition（分区）

Partition是Topic的物理拆分，一个Topic可以被拆分为多个Partition，这些Partition会分布在Kafka集群的不同Broker节点上。核心作用有两个：一是实现水平扩展，多个Partition可以并行处理消息的读写，提升整体吞吐能力；二是保证有序性，单个Partition内的消息是严格按发送顺序存储和消费的（跨Partition则无法保证全局有序）。

## 3. Replica（副本）

Replica是Partition的“备份”，每个Partition会有多个副本，分为Leader副本和Follower副本：Leader副本负责处理所有针对该Partition的读写请求，Follower副本仅同步Leader副本的数据。核心作用是保证高可用，当Leader副本所在的Broker节点故障时，Kafka会自动从Follower副本中选举出新的Leader，避免数据丢失或服务中断。

## 4. Broker（节点）

Broker就是Kafka集群中的单个服务器节点，每个Broker会存储Topic的部分Partition数据，同时处理生产者的消息发送请求、消费者的消息订阅请求，以及副本同步等核心逻辑。

## 5. Producer（生产者）

Producer是消息的发送方，比如电商系统中生成订单后，订单服务就是生产者，会把订单消息发送到Kafka的Topic中。生产者支持多种特性，比如指定消息发送到哪个Partition、对消息进行压缩、异步发送以提升效率等。

## 6. Consumer（消费者）

Consumer是消息的接收方，比如订单消息发送后，库存服务作为消费者，会从对应的Topic中订阅并消费消息，进而扣减库存。消费者支持批量消费、手动提交消费位置等特性，保证消息处理的可控性。

## 7. Consumer Group（消费者组）

Consumer Group是多个消费者组成的“分组”，核心规则有两个：一是同一个消费者组内的多个消费者，会共同消费同一个Topic的不同Partition（每个Partition只能被组内一个消费者消费），实现负载均衡，避免重复消费；二是不同消费者组可以独立消费同一个Topic的所有消息，实现消息广播（比如订单消息既给库存服务消费，也给统计服务消费）。

## 8. Offset（偏移量）

Offset是消费者在Partition中的“消费位置标识”，相当于看书时的“书签”，记录了消费者已经消费到该Partition的哪一条消息。核心作用是保证消费的连续性，消费者重启后可以从指定的Offset继续消费，既避免重复消费已处理的消息，也不会漏消费未处理的消息。

## 9. 集群协调组件（Zookeeper/Kafka Controller）

早期Kafka依赖Zookeeper管理集群元数据（比如Topic/Partition的分布、消费者组的状态）、选举Leader副本；Kafka 2.8+版本支持脱离Zookeeper，改用Kafka Controller作为集群协调器，核心作用是统一管理集群的核心状态，保证集群正常运行。

## 10 补充核心特性

- 消息持久化：消息写入Partition后会持久化到磁盘（而非仅存于内存），可以配置消息的保留时间或保留大小，支持海量消息的长期存储；
- 高吞吐：基于“顺序写磁盘”“批量读写”的设计，Kafka单机就能支撑10万+ TPS的消息处理能力；
- Exactly Once（精确一次）：通过事务和幂等性机制，保证消息的生产和消费仅被处理一次，解决分布式场景下的重复消费问题。

### 4. 生产者实现（发送消息）

```java
package com.example.kafkademo.producer;

import lombok.extern.slf4j.Slf4j;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.kafka.support.SendResult;
import org.springframework.stereotype.Component;
import org.springframework.util.concurrent.ListenableFuture;
import org.springframework.util.concurrent.ListenableFutureCallback;

import javax.annotation.Resource;

/**
 * Kafka生产者：实现同步/异步发送消息，带发送结果回调
 */
@Component
@Slf4j
public class KafkaMessageProducer {
    // Spring Boot自动配置的KafkaTemplate，直接注入即可使用
    @Resource
    private KafkaTemplate<String, String> kafkaTemplate;

    // 统一管理Topic名称，避免硬编码
    public static final String TEST_TOPIC = "test_topic";

    /**
     * 同步发送消息（简单场景使用，会阻塞直到发送结果返回）
     */
    public void sendSyncMessage(String message) {
        try {
            // 发送消息到指定Topic，key为null时由Kafka自动分配Partition
            SendResult<String, String> result = kafkaTemplate.send(TEST_TOPIC, message).get();
            log.info("同步发送消息成功：topic={}, partition={}, offset={}, message={}",
                    result.getRecordMetadata().topic(),
                    result.getRecordMetadata().partition(),
                    result.getRecordMetadata().offset(),
                    message);
        } catch (Exception e) {
            log.error("同步发送消息失败，消息内容：{}", message, e);
        }
    }

    /**
     * 异步发送消息（生产环境推荐，非阻塞，带回调处理成功/失败）
     */
    public void sendAsyncMessage(String message) {
        ListenableFuture<SendResult<String, String>> future = kafkaTemplate.send(TEST_TOPIC, message);
        // 注册发送结果回调
        future.addCallback(new ListenableFutureCallback<SendResult<String, String>>() {
            @Override
            public void onSuccess(SendResult<String, String> result) {
                log.info("异步发送消息成功：topic={}, partition={}, offset={}, message={}",
                        result.getRecordMetadata().topic(),
                        result.getRecordMetadata().partition(),
                        result.getRecordMetadata().offset(),
                        message);
            }

            @Override
            public void onFailure(Throwable ex) {
                log.error("异步发送消息失败，消息内容：{}", message, ex);
                // 失败后可执行重试、告警、写入死信队列等逻辑
            }
        });
    }
}
```

### 总结

1. Kafka核心逻辑：Topic是消息分类维度，Partition实现Topic的物理拆分（保证吞吐和单分区有序），消费者组实现消息的负载均衡/广播，副本保证高可用，偏移量保证消费连续性；
2. Spring Boot整合关键：依赖 `spring-boot-starter-kafka`实现自动配置，生产者用 `KafkaTemplate`发送消息（异步+回调更适配生产环境），消费者用 `@KafkaListener`监听Topic，手动提交偏移量提升消费可靠性；
3. 生产环境建议：消费者组ID按业务隔离，关闭自动提交偏移量，消息序列化优先使用JSON（支持复杂对象），针对消费失败的消息增加重试/死信队列机制。
